# Agent Pi DSH 3.7.5 实施计划

基线：v3.7.4 / 2dadcc9；沿用现有发布工作树及分支。实施与产物验证证据见 [3.7.5 验证记录](verification-3.7.5.md)。

## 目标与边界

以客户当次任务目标和项目实际适用的专业依据组织工作，形成“交流澄清 → 适用性评估 → 证据补足 → 计算和专业执行 → 文件交付 → 验收和修订”的完整链条。覆盖通用企业文档、表格、调研、汇报，以及跨国别投标、施工图读图、工程量计算和施工方案。

保留 DSH 原生 agent loop、工具执行、工作流、子智能体、权限与停止机制；产品功能通过 Cordis 服务、工具、提示上下文和客户端扩展实现。不得建立第二套模型执行循环。保留完整 Univer Office、CAD、项目计划预览、文件栏、项目快照、显式知识库选择及既有用户流程。新增能力不能恢复用户主动卸载的插件。

“全量”指落实本计划的完整专业任务链条及兼容迁移，不把工作缩小为提示词或界面调整。不宣称预装全球所有规范，也不把模型生成的规则当作经过核验的规范；未知体系走证据发现和适用性评估。

## 已核对的问题

1. 通用投标流程含 CIDB、BCCEI、SANRAL、央企审批等特定体系内容，需要按项目适用条件加载。
2. BOQ 推导默认依赖 C5.1 范例及纯直接成本质量配置，需区分通用逐项推导方法、特定计量计价规则及报价口径。
3. 递交文件审计固定要求四类专业报告，应由实际必交文件及评分点驱动，并保留旧项目兼容。
4. 全文解析、当地尽调、成本与资源、实施策划、正式递交之间需要可检查的数据关联和变更传播。
5. 去 AI 味已有写作技能，但缺少随当次专业方向自动装配和针对实际成果的质量检查。
6. 工作台贡献与用户 JSON 流程已存在；还需统一覆盖工具、技能、模块及能力限制，让 UI 与内部发现读取同一目录。

## 执行顺序与交付

### P0：基线与依赖审计

- 检查工作树、运行时和现有测试；记录升级前的失败，保留未提交用户工作。
- 查询官方 DSH Release、npm 注册表和插件上游；记录当前版本、候选版本、兼容范围、决策及验证。
- 只升级兼容且完成回归的依赖；不绕过插件兼容检查，不把存在于磁盘当成运行时可用。
- 交付：本计划、`docs/dependency-audit-3.7.5.json`、基线验证记录。
- 验证：版本与来源可追溯；Office/CAD 完整性及 DSH pin 保持可核验。

### P1：统一专业任务数据

- 新增专业任务数据结构和持久化：目标、范围、受众、输出格式、期限、语言、输入版本、项目适用体系、用户已确认条件、证据缺口、计划、交付及验收项。
- 明确证据状态：源文件事实、核验外部事实、工程推导、商业假设、待核实；记录定位、日期、地区、版本、适用性。
- 任务按会话隔离并支持重启恢复、修订检测；客户变更令依赖该输入的计划和成果待复核。
- 验证：多会话隔离、重启恢复、并发保存冲突、变更影响传播、未知事实不会被升级为已核验。

### P2：Cordis 专业任务引导与统一能力目录

- 增加原生产品插件 `dsh-agent-pi-task-guide`，提供任务与能力服务、模型工具及 HTTP 状态入口。
- 能力贡献含插件归属、版本、专业、适用/排除条件、输入/输出、所需工具/技能、核验方法和补足措施。
- 通过原生运行时适配实际工具、技能及工作台流程；用户自建流程纳入目录，保持声明式存储。
- 卸载/停用撤销能力与路由；执行前再次检查实际可用性；引导插件可独立于工作台使用。
- 使用 DSH 原生上下文和用户提问服务引导需求，执行仍由 DSH 原生工具/工作流负责。
- 验证：插件贡献与释放、重复贡献拒绝、启停一致、无工作台的普通任务、第三方领域贡献与能力不足路径。

### P3：项目体系识别与尽调策略

- 建立按项目组合的适用体系：国别/地点、业主、采购与资金体系、合同及版本、计量计价规则、技术规范及版本。
- 通用阶段移除无条件的特定国家/机构要求；南非等规则作为条件贡献和参考来源保留。
- 网络尽调按缺口逐项进行，记录来源、日期、适用性、复核状态；证据不足只能形成待核实条件或推导情景。
- 公开市场资料不能替代项目地质、客户实际资源、企业资质业绩和正式报价；关键承诺及最终提交继续由客户决定。
- 验证：中国、纳米比亚、南非及未知体系的条件化测试，币种不被单独当作法域，冲突来源不被静默覆盖。

### P4：全文解析与项目要求覆盖

- 增加逐文件/页/表/图/附件覆盖登记，保留不可读、缺失和补遗状态；全文覆盖与摘要分开检查。
- 从原文件定位提取项目条件、评分点、技术要求、计量规则、BOQ、必交表单和递交要求。
- 招标要求建立稳定标识及证据定位，关联下游工作包、计算和文件；修改补遗标记对应下游成果待复核。
- 验证：表格/附件漏项、扫描失败、版本补遗、BOQ 原始身份、完整覆盖与局部解析的区别。

### P5：BOQ 成本与资源逐项推导

- 通用五步方法按每项清单建立范围、工法工效、单位资源消耗、价格/成本与对账链。
- 区分实物清单、暂列金额、百分比、计日工、仅报单价等项目；仅按适用计价规则计算。
- 确定性计算单位资源消耗乘工程量、成本及分项汇总，核验单位、范围、重复计入和原清单对账。
- 内部成本与投标报价分开；费用、税费、利润和风险的计入取决于项目依据。
- 资源总消耗与时间分配/峰值分别检查；材料、机械、人工和费用假设变化传播至策划、进度、现金流及递交文件。
- 验证：具有明确预期值的成本/资源案例、传递项、重复范围、单位不匹配、工效变化及金额对账；保留现有公式工作簿交付。

### P6：实施策划与实际递交清单

- 从工作包、BOQ 与资源推导生成施工组织、工法、进度资源、采购临建、质量安全环境、成本现金流等当次所需成果。
- 将招标评分点和必交清单映射到内容、模板和实际交付文件，覆盖资格/声明/承诺/偏差/人员设备等表格文案。
- 根据本次任务范围决定必须成果；旧项目无新清单时继续使用原检查口径。
- 最终审计分别记录文件存在、内容覆盖、专业检查、格式、跨文件一致性和签署授权；生成文件不等于可以提交。
- 验证：不同招标清单、只做部分任务、模板继承、缺表单和缺签署、跨文件不一致、旧项目快照。

### P7：施工图、工程量与施工方案

- 按图纸版本、专业、单位、范围、计算口径、现场条件及成果用途进行任务引导。
- 读图结果和工程量保留图纸位置/构件/尺寸/计算式/数量联系；几何解析和视觉判断分开标记。
- 施工方案按项目工法生成步骤、资源、参数、检验和异常处理；能力不足时提供可执行补足路径。
- 验证：图纸重复视图、单位/版本缺口、不可读取格式、工程量计算和方案输入的任务适用性。

### P8：自动专业写作与质量检查

- 按专业、文件类型、受众、语言和客户模板装配写作要求，专业任务自动应用，普通对话保持轻量。
- 检查专业术语、来源、数字与计算、可执行步骤、空泛/重复内容、内部工具信息；不能仅靠禁词判断质量。
- 正式递交文件从内部底稿派生，不泄漏系统流程说明；缺事实不编造具体内容。
- 验证：有依据的具体写作、空泛段落、模板要求、不同专业/语言，以及正常专业词汇不被误删。

### P9：客户任务界面

- 在现有对话与工作台提供任务目标、待确认问题、计划及进度、能力限制/补足、成果与验收展示。
- 客户可以修改目标和范围、回答关键问题、选择成果、查看来源与复核状态；界面读取同一任务与能力服务。
- 复用现有 React 风格和语言机制；桌面及窄窗口测试，不引入新 UI 框架。
- 验证：真实浏览器任务创建/修改/恢复、目录与插件状态一致、错误和空状态、中文/英文、窄窗口及无控制台错误。

### P10：升级、构建与交付

- 更新当前应用版本、锁文件、产品插件版本及发布说明；保留既有 3.7.4 发布记录不可变。
- 将新插件和依赖纳入 profile 初始化、跨平台运行时及打包校验；不覆盖客户主动配置。
- 执行业务、主机、客户端、profile、Office/CAD、版本迁移回归；构建客户端并冷启动。
- 按现有 Windows 打包流程交付可直接验证的 3.7.5 安装包、哈希及构建/验证记录。发布到外部 Release 仅在另行授权后执行。
- 验证：安装包实际版本、新插件真实加载、Office/CAD/计划入口仍可用，旧项目可读，源码/运行时/安装包一致。

## 完成审计

每项需求对应实际代码、业务行为测试及适当的运行验证。绿色测试只有在覆盖对应需求时才作为完成证据。模拟样例与真实文件/浏览器验证分别报告，不把回放或静态测试写成付费模型真实业务验收。依赖审计明确“升级、保留、受兼容性限制”，不报告尚未核实的最新版。

实施完成后填写 `docs/verification-3.7.5.md`，逐项记录 P0–P10 的证据、未通过项、实际安装包路径和校验值；所有必需项证明完成前保持任务进行中。
