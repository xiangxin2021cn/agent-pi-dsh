## 本次更新

### 插件市场：1.66.8 → 1.66.9

采用 [dshmarket 1.66.9 官方 npm 包](https://registry.npmjs.org/dshmarket/1.66.9)，发布于 2026-10-05 17:04:08 UTC，源码提交 [`e03c7a035596c96b51b47ad2e44209bc6029334d`](https://github.com/dsh-market/dsh-market/commit/e03c7a035596c96b51b47ad2e44209bc6029334d)。原始归档 1,179,290 字节，SHA-1 为 `ad3eafd579805bac8e598fbed66c95eaac3f6c02`；下载后逐字节校验 npm SHA-512 integrity，完整值保存在 `vendor/core-plugins.pin.json`。

用户仍从应用设置中的插件市场进入。主要变化：

- 普通库或 CLI 依赖不再显示成市场可以安装的插件更新；后端也拒绝这类误操作。
- 某些 pnpm 版本安装发布归档时缺少 integrity 的特定错误，可以回退一次到该目录条目本身的 GitHub 源码；不同来源或其他错误不能触发回退。
- 插件更新后，如果包仍在但加载列表中的条目消失，会记录具体名称；不会擅自恢复用户关闭的插件。
- 改善桌面宿主定位、Windows 文件占用提示、插件开关状态诊断、截图关闭按钮位置及安装能力说明。

Agent Pi 既有适配通过原始 1.66.8、当前产品源码、原始 1.66.9 三方合并保留：宿主版本门槛、完整 Office、Electron 管理的重启、Agent Teams 与压缩模块保护、已知 IM/邮件兼容边界和当前 Office 目录说明均保留。使用 `node scripts/build-dshmarket.mjs` 重建适配后的服务端与客户端；来源与适配文件摘要见 `vendor/dshmarket/AGENT-PI-ADAPTATION.json`。

## CAD 原生构建复用审查

3.8.1 继续使用原始 CAD 构建提交 `1aef6820ebc450125788158a4b2d1706115cdd10` 及其对应源码归档。对照该提交审阅 `http.ts`、文件预览界面及根 `package.json` 的实际差异：既有 3.8.0 宿主新增了 DWG 转 DXF 接口、转换状态和内容哈希缓存，属于 **CAD 宿主集成扩展**。原生 viewer、LibreDWG 构建工具链和构建输入未因此改变。

`scripts/cad-integration-compatibility.mjs` 将这次宿主扩展单独记录于验证结果的 `hostExtension`，不将其声明成“非 CAD 改动”。检查固定 shared 文件前后内容 SHA-256、新增的 `cad-convert.ts` / `cad-convert-worker.mjs`、宿主依赖声明和完整锁文件；仅根包的应用版本字段允许变化。原始源码身份、文件模式、其他 CAD 输入与未提交改动检查继续生效，后续任意被锁定内容变化均须重新审阅。

转换工作进程从已验证的 `tender-web/lib/cad-viewer/workers` 加载原生引擎，不使用 npm 包中的未经本项目构建核验的 WASM。转换前验证工作区边界，输出通过 ASCII DXF 完整性检查后才发布缓存；失败时保留原 DWG 并报告错误。此检查不证明所有 DWG 实体均能无损转换，也不代表自动算量已完成。

`node --test scripts/cad-integration-compatibility.test.mjs` 在宿主运行 32 项全部通过，包括精确内容、完整配套文件、后续改动、依赖改动、转换器缺失/模式变化和未提交改动的拒绝回归。首次沙箱运行因临时 Git 仓库配置写入被拒绝而未执行到断言；同一命令在宿主重跑通过。

正式打包前，先运行 `cad-clean-release.mjs verify` 检查原归档和运行时，再在最终提交上运行 `cad-integration-compatibility.mjs --root . --manifest .codex-temp/cad-clean-output-release-362/cad-viewer/CAD-CLEAN-BUILD.json` 并保存新的复用证明。旧证明仅绑定旧提交，不能替代本轮检查。
