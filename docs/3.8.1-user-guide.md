# Agent Pi DSH 3.8.1 使用指南

3.8.1 将投标要求、评分细则、章节计划、企业材料和当前成稿连接到同一份响应记录。用户在主对话说明目的，助手读取资料并登记计划；“本次任务”和“专业化工作台”展示同一份响应对照。评分覆盖、文件定位检查、内容审阅和最终人工决定分别记录。

## 从哪里开始

1. 打开或创建项目对话，选择本次使用的招标文件、补遗、图纸及企业资料。
2. 在专业化工作台选择适用流程。中国项目使用“中国招投标与响应复核”；已有其他投标项目继续使用原流程。
3. 在主对话直接描述任务。助手负责读取资料、逐步澄清、登记要求和编写计划，用户不需要填写评分 JSON 或逐章表单。
4. 在“本次任务”的“响应对照”查看详细情况；工作台项目概览也显示同源对照，主对话显示紧凑的响应进度和缺口。

只有已绑定投标项目才使用共享响应工具，普通聊天不会因此自动变成投标任务。页面为空时，先让助手读取并登记当前项目的要求；仅上传文件或说到“标书”，不代表已完成分析或生成。

## 可直接使用的对话示例

### 先策划技术标

> 这是本项目的招标文件、补遗和企业资料。先帮我策划道路工程技术标：区分资格与实质性要求、评分点和提交格式，保留原文出处；按招标人的目录建立章节计划，告诉我缺哪些资料。明确的部分先推进，涉及人员承诺或方案取舍再问我。

预期结果：系统形成已登记要求、评分原文及子点、章节计划和材料缺口。“已规划”表示建立了回应关系，不表示已经写好或能获得对应分数。

### 让工程依据进入正文

> 按已确认计划编写交通组织和排水施工章节。请使用本项目图纸、复核过的工程量、施工分段及资源工期计划；把使用的计算文件关联到对应章节。图纸尚未读清的地方保留缺口，不要从旧标书补数字。

助手可使用实际已安装的 CAD、PDF、道路、市政、钢筋、BIM 等插件，并将所用文件关联到章节。建立模型或提取图纸文字，不等于已经完成构件覆盖和工程正确性复核。

### 复核成稿与补遗影响

> 请逐项对照最新评标办法检查这份技术标。定位每个评分子点在当前成稿中的章节或段落，指出材料不适用、漏答及缺乏计算支撑的地方。新补遗只修改交通导改条件，请列出受影响的章节并复核，无关内容继续使用。

系统检查实际文件、定位和登记的依赖。修改某一要求记录只影响关联响应；修改一个来源文件的字节，会使引用该文件的响应待复核。本版没有宣称能自动判断 PDF 某一页的修改只影响哪个句子。

## 响应对照怎么看

| 内容 | 含义 |
| --- | --- |
| 要求及评分原文 | 已登记的资格、必答要求或评分项；可展开原文、子点与分档条件 |
| 来源 | 招标文件、补遗或其他登记资料的位置；有实际文件时可以打开 |
| 对应章节 | 计划回应的章节，以及原件引用、条件化改写或项目生成方式 |
| 材料与工程依据 | 所选企业证据或工程文件及其检查提示 |
| 当前成稿 | 已登记的实际文件和定位；点击打开当前成果 |
| 待复核 | 有未确定材料、尚未自动定位的格式、内容审阅未通过等问题 |
| 已变化 | 文件、关联要求、材料或其他明确依赖变化，旧复核记录已不适用 |
| 当前稿已记录复核 | 当前文件与定位检查及已登记的内容审阅满足要求；不是程序独立验真或客户验收 |

摘要分别计数计划、成稿、证据准备和复核情况。一个章节关联多个评分项时，响应数量不会重复累计。页面始终说明统计仅覆盖已登记条目；未读取的资料和页面仍需在任务覆盖记录中核对，不能据此推定完整标书全部覆盖。

## 企业材料如何复用

- **原件引用**：证书、业绩证明、授权文件保持原件和事实，不让模型改写证明内容。
- **条件化改写**：管理制度、成熟工法、岗位职责框架可以调整，但要核对本项目条件。
- **项目生成**：施工部署、进度、资源、重难点等从当前资料及工程依据产生。

材料记录核对所属主体、预期主体、用途、适用条件、有效期、人员/资源可用性、授权及复核依据。未提供、未核验、过期或错主体的资料保留缺口。“有文件”不表示“满足资格”。知识库仍使用原有固定版本与引用，不需要重新导入一套资料库。

## 模板如何选择

招标人强制目录、表格、顺序和格式优先。企业历史样稿用于参考结构与深度，可以按本项目要求裁剪或重组，不再机械要求“旧模板十二章，新标书也十二章”。如果用户明确要求的格式与招标文件冲突，助手应说明影响并澄清。

暗标中的身份信息、篇幅或格式限制以本项目文件为准；本版不内置一个适用于全国所有项目的暗标规则。

## 专业深度和工作台流程

专业深度开关沿用现有用途，用于要求更深入的方法、证据和审阅。关闭它不会取消来源、材料有效性和必答项等基础检查，也不会删除已有记录。

新建中国项目采用七个阶段：

1. 项目制度与原始清单。
2. 招标要求与补遗解析。
3. 资格与响应证据。
4. 评分与章节响应策划。
5. 报价与工程复算差异。
6. 技术标编写与逐项复核。
7. 递交前人工检查。

仅做技术标或非工程任务时，按用户范围处理，不编造 BOQ、价格或零数量来满足流程。阶段成果应注明不适用的工作及依据。

已有项目继续保留创建时的工作流快照、成果和历史，不自动改写为七阶段。它们可以在主对话调用新的响应策划与复核，并查看响应对照；新建项目采用新版默认流程。旧响应没有章节计划时显示缺少结构化计划，不会升级后自动标成已复核。

中国投标与原投标工作流按模块和项目编号分别保存响应记录，即使项目同名也不会混用账本或复核结论。中国项目的资料同步会传播已登记来源的“被替代”“不可读”等明确状态；旧文件不会因为仍在磁盘上就继续作为有效依据。只是在本轮没有选中的来源不会被擅自删除。

## 文件检查与能力边界

- 文本/Markdown 支持指定行及章节中的真实摘录定位；DOCX 支持正文段落及标题定位，段落行号不是排版页码。
- PDF 等暂未支持自动定位的格式会记录真实文件哈希和提供的位置，同时保留人工定位待复核。应使用现有 PDF/Office 工具抽取和查看排版。
- 已登记评分子点需要逐点关联当前正文定位与审阅。仅找到一段文字，不能证明所有评分子点都已充分回答。
- 文件哈希只能证明版本，不能证明技术正确。内容审阅明确记录模型或实际人员身份和说明，不代表官方评标、资质验真、客户接受或中标概率。
- 未声明的外部依赖无法自动发现变化。工程插件的计算质量和覆盖检查仍要独立完成；将工程成果文件关联到章节不等于批准计算结论。
- 本版不自动签章、加密或向交易平台递交，不自动获得企业证照/信用数据库权限。

Windows 开箱即用 BIM、九个工程插件及其原有边界见 [3.8.0 使用指南](3.8.0-user-guide.md)。本版保留对应运行库和 Office，不把写作能力升级描述为 CAD 自动完整识图或任意图纸自动建模。

## 排查

- **看不到响应记录**：确认当前对话已绑定正确项目，再让助手读取要求并建立响应计划；文件上传本身不产生评分矩阵。
- **有章节但没有成稿入口**：让助手生成实际文件并登记定位检查，不要只在聊天里写“已完成”。
- **材料一直待复核**：查看主体、日期、授权、可用性和出处是否缺失。让助手说明依据，不能直接把状态改成通过。
- **修改文件后变为待复核**：这是版本保护。按变更重新查看当前文件和对应子点，再记录复核。
- **刷新状态**：工具执行后界面通过会话事件及定时读取刷新。读取损坏记录时会显示错误，不将错误显示成空项目。

开发与接口说明见 [3.8.1 改造方案](3.8.1-development-plan.md)；新增字段通过应用内部 `tender_workspace schema` 获取，用户无需手工填写。
