## 使用路径

用户在主对话表达目标，专业深度负责当前检查规则；本次任务展示共同目标、持续约束、来源、发现和交付核验。工作台读取同一任务/项目和实际文件，不建立第二套目标或模型计划。

“继续推进”先由宿主生成实际阶段预览和短期指纹，再明确启动当前阶段。宿主在 native inbox 写入唯一控制消息，保存派发与结算事件。旧浏览器事务不能授权继续执行。输入、前序成果或项目目标变化时，旧尝试失效，需要按新的预览明确恢复；人工门和暂停始终有效。

成果核验通过后仍等待用户验收。方法提炼先成为候选；可在另一个真实任务中选择独立输入、人工预期和实际输出验证，再在模块管理明确发布。固定案例当前采用字节一致验证，界面明确其适用限度。

模型导入的知识保留为生成内容，不能自行标成原始资料；知识传递包在人工导入时保留来源类型、适用地区与有效期。选中知识的上下文保留返回引用中的完整版本号；人工清空有效期会生成新的元数据版本，旧版本继续保留。人工技能操作仅接收应用同源 JSON 请求，阻止跨站请求冒充案例确认或发布批准。

产品、业务核心、配置迁移、真实 Electron 与最终打包程序分别验证。具体日志位于 .codex-temp/long-horizon-product-final.log、long-horizon-business-final.log、long-horizon-release-final.log 和 output/long-horizon-379/evaluation.json；真实界面截图与日志保存于隔离验证目录。

冻结源码验证：产品 Node 回归 724/724，业务核心 Bun 回归 125/125，配置迁移与发布规则回归 55/55；长期任务专项评估 102/102、零跳过，通过。专项计数已经包含在产品回归中，不重复相加。真实隔离 Electron 33 项检查通过，包含原生派发收据、刷新去重、暂停保持、官方历史查询、约束撤销、实际成果核验以及知识和技能面板。另有两个并存会话的实际 DOM 回归，验证工作台技能、核验、派发与知识操作始终采用所属会话。客户端构建通过；旧版本测试的固定历史断言未为了当前版本修改。

验证程序使用隔离 profile、临时工作区与空模型密钥，不操作用户当前运行的应用。本次证明状态、消息、实际文件版本、权限及交互的传递和停止行为。尚未用真实长程模型任务证明专业结论质量或提升率，没有进行模型训练，也没有测量论文 H2/H3 能力。引用支持由执行者结合独立原件明确复核，系统不靠字符串定位宣称语义正确。

所有改动保持应用版本 3.7.9，DSH_PIN 不变。使用 scripts/pack-win.ps1 完整重建本地 Windows x64 安装包，禁止复用旧 runtime/unpacked；交付校验以安装器实际 SHA256、干净源提交、官方 DSH/Office/CAD 回执及隔离打包程序验证为准。
