# Agent Pi DSH 3.8.3 使用指南

本版重点是把“主对话—本次任务—专业化工作台”接成可操作的共同任务。内核升级为 DSH 0.2.1-alpha.4，组件明细见 [核心组件更新](3.8.3-core-plugin-updates.md)，实施和验收要求见 [开发方案](3.8.3-development-plan.md)。

## 从自然语言开始

在主对话直接描述目的、资料和实际用途，例如：

> 请检查这套结构施工图，先确认混凝土工程量依据和可能漏项。结果给项目经理使用；没有依据的尺寸不要推测计入。

普通任务无需先建专业项目，也无需填完任务表。助手应阅读已有材料、形成当前理解，只追问会影响方案或验收的关键问题。用户明确表达的条件、资料事实和系统推测分别记录。

对话中的目标卡和“本次任务 → 任务概览”使用同一份任务记录及操作。目标、当前步骤、发现、来源覆盖、专业复核和交付检查可在这里持续核对。绑定项目时另外显示项目总目标和当前阶段，阶段目标不会覆盖项目总目标。

## 直接调整执行

| 按钮 | 怎么使用 | 系统会做什么 |
|---|---|---|
| 确认当前理解 | 暂定目标准确时点击；明确任务无需等待此确认才执行 | 确认当前目标，不将未审阅的专业依据升级为用户确认 |
| 补充或调整要求 | 用一句自然语言说明改变，例如“先检查工期，保留已核实算量，报告给项目经理使用” | 保存用户原文及消息身份；运行中交给当前执行器，空闲时提交主对话 |
| 重新规划 | 可补充此次重排应采用的条件，也可直接要求重排 | 主执行器依据最新目标、有效成果和缺口调整计划 |
| 暂停执行 | 不想继续当前分析时点击 | 暂停自动接续并请求当前主执行器及子任务停止；保留要求、依据和成果 |
| 继续任务 | 暂停后或需要推进未完成工作时点击 | 核对当前状态和门禁，再交给当前选定执行器 |
| 核验已登记成果 | 已登记输出文件后点击 | 请求检查实际文件、要求覆盖和未完成专业复核 |

提交后查看回执，区分已交给当前回合、等待执行、已停止和受阻。保存要求不代表智能体已经完成理解和修改；执行器会在后续边界读取新要求并反馈影响。最近提交的要求会保留在操作区，方便核对。

若自动接续已暂停但当前执行仍在收尾，界面会明确提示，可再次请求停止；不把取消信号当作全部工作已停止。刷新或重启保留暂停状态。尚未送达的准备命令在重启后失效，不会自动重复执行，可核对后重新点击。

“修正目标”“项目依据”等高级字段仍可低频编辑。点击“保存并调整执行”会先保存用户实际修改的字段，再以可读摘要通知主执行器。若通知失败，会分别提示已保存和未确认执行；不要把保存成功当作任务已改完。

## 与发现、问答和工作台配合

发现卡展示“发现—依据—对当前目标的影响”。点击“补充或调整处理”可以提供事实、决定或处理要求；意见关联到这一项发现，提交本身不会将问题自动标为已解决。依据按钮打开实际来源，资料内容不作为新的用户指令。

原生问题在原生问答卡中回答。任务页提供前往问答入口，普通继续按钮不会替用户回答问题、批准权限或签名。

工作台人工门仍需要查看当前阶段范围和实际成果后明确批准。任务卡使用当前显示成果的版本指纹审批，批准后读取最新任务并继续；若续跑受阻，阶段批准与续跑失败分别显示，可核对原因后重试继续，无需重复批准。

任务页、对话卡和工作台启动遵循当前 DSH / Codex 主执行器选择。原生 Codex 必须在桌面应用中使用，并保持有效登录才能开始新工作；登录失效时仍能请求停止。Codex 不会把同一任务额外投递给 DSH。绑定项目的旧 DSH 自动调度在 Codex 工作时保持隔离；后续阶段继续使用已有工具和人工门。

## 专业深度与工程插件

“专业深度”是用户选择的专业检查政策，与当前任务共享来源、计算依据、缺口和交付记录。切换开关不会把缺口变成通过、授予阶段批准或客户验收，也不会清除已完成的专业检查。设置随任务和项目变化刷新，不另开一份脱离主对话的任务。

完整 Univer Office、九个工程插件、CAD 大图修复及 Windows x64 内置 BIM 继续保留。可在对话中请求对应工作，使用实际已安装插件能力；卸载或禁用插件后不会被升级静默重新打开。

CAD 仍区分结构读取、几何/语义覆盖和工程量复核。二维预览、DXF 导出或提取内嵌对象成功都不等于全面算量。中国平法钢筋需要本项目适用且获准使用的规则包、构件和节点条件；未知项不能按零量处理。Windows BIM 可基于已确认参数创建支持的 IFC 构件，不能从任意 CAD/PDF 一键得到完整 BIM；macOS/Linux 仍需对应平台外部引擎。详见 [既有工程能力边界](3.8.2-user-guide.md)。

## 受阻时怎么处理

- “任务已更新”：读取最新状态，核对别人或执行器刚刚改变的内容，再提交；旧版本不会强行覆盖新状态。
- “等待用户审批 / 原生问题”：先打开对应阶段或问答卡处理。继续操作不替代这些决定。
- “预算限制”：检查现有预算状态，不会因重新规划或继续自动增加预算。
- “尚未确认停止”：自动接续已冻结，当前执行仍需停止确认；查看主对话后可重试暂停。
- 原生执行器拒绝或断连：核对登录、工作区及原生执行状态。应用显示失败，不会偷偷切换成 DSH 重跑。

本版确定性协议及界面回归只验证操作链、状态与边界，不保证付费模型在真实长程任务中的所有判断质量。客户验收、专业复核和签署仍保留独立判断责任。

暂停前已排队的输入会以原消息身份持久暂存，可在操作区展开核对。继续 DSH 时恢复到原会话和队列；暂停后的最新修正优先。原会话尚未加载、已归档或工作区变化时会明确阻止恢复。选择 Codex 继续会保留旧 DSH 队列，不额外唤醒 DSH。

主对话的真实新消息在持久入队时即同步到共同任务；取用、恢复或重复消息不会覆盖后来要求。执行器更新结构化理解和成果需要实际执行，登记及时不等于专业判断已完成。

工作台“继续推进”和“恢复事务”也通过同一条任务继续链；任务页暂停后可从工作台恢复。仍需先处理原生问题、实际阶段审批和预算限制。暂停事务只冻结项目自动接续；需要同时停止当前对话和子任务时使用“暂停执行”。

暂停中仍可人工调整要求、重新规划或核验成果；这些操作保持自动接续暂停，只有明确点击继续才恢复自动执行。

工作台“DSH 自动阶段执行预算”读取当前已登记值，仅提交本次明确编辑的轮次、token、累计时间、无进展次数或金额上限。未编辑时继续沿用原预算，不重置实际用量、执行记录或 Goal 预算。清空可选金额上限表示明确取消；既有 Goal 预算仍需单独处理。预算在下一次“继续推进”或“恢复事务”时提交，失败原因会显示。原生 Codex 不使用这组 DSH 阶段预算，因此控件在 Codex 主执行时禁用。

Windows 内置 BIM 请使用默认安装目录。过深的自定义路径仍可能触发 Windows 原生库路径长度限制：本轮在 262 字符的构建路径下观察到加载失败，将相同完整载荷复制到短物理目录后，默认引擎及完整界面回归通过。此次不宣称已解除该原生路径限制。


## 2026-10-17 Codex 入口修正（仍为 3.8.3）

重启后打开历史对话，消息首屏可能先于后台执行代理恢复完成。旧入口会在此时拒绝 Codex 发送；本次修正等待官方会话控制器完成同一会话的恢复，再检查工作区、主会话、权限及执行占用，不要求先向 DSH 发送一轮消息。

在设置中登录 ChatGPT 并确认可用 Codex 模型，打开对话后从输入栏选择 Codex，正常填写任务并发送。正在运行的 DSH、未处理队列、归档或工作区不匹配仍会明确阻止启动，不会自动丢弃消息或启动另一个写入者。

发送失败时会显示清理后的具体原因，原草稿和附件保持可重试；原生执行面板也保留模型或协议返回的原因。认证信息不会作为错误详情展示。模型查询的客户端版本标识已同步为 3.8.3。

已经安装 3.8.3 的用户也需使用本次重新生成的安装包覆盖安装。先保存文件并退出应用，沿用原默认安装目录；版本号不变，使用同名 SHA256 和构建回执区分安装包。
