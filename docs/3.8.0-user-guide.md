# Agent Pi DSH 3.8.0 新增功能使用指南

本指南对应已经发布的 **3.8.0**。重点说明实际入口、对话用法、结果位置和当前能力边界；这里的示例参数仅用于体验功能，不是工程设计依据。

## 先回答：BIM 从哪里用？

**直接在主对话中提出 BIM 任务即可发起操作。** Windows x64 安装包已内置 Python 和 IfcOpenShell，默认无需另装 Python、conda 或建模软件。主对话智能体根据请求调用工程工具，工具在本机运行 IFC 引擎。

“开箱即用”指引擎及其依赖已随安装包准备好。当前没有单独的“新建 BIM”按钮，也没有输入某个关键词便无条件自动执行的机制。只说“创建 BIM 模型”可以作为任务开头，但还需明确构件类型、尺寸、单位、位置和输出文件；缺失条件应在对话中补充，不能凭空推测。

这几件事要分别理解：

| 操作 | 实际作用 |
| --- | --- |
| 在主对话提出任务 | 由智能体理解请求、检查材料、调用工具并报告结果；需要可正常使用工具的主执行模型 |
| 开启“专业深度” | 调整专业检查与引导要求；不是安装或启用 BIM 引擎的开关 |
| 选择“工程图纸与算量”工作台 | 为较长的工程任务提供阶段、材料和项目上下文；普通对话也可以调用已加载的工程工具 |
| 打开“本次任务”或项目工作台 | 查看已记录的目标、依据、发现、计算和缺口；不是必须先填写的 BIM 建模表单 |

**macOS / Linux 的 3.8.0 没有内置 Windows IFC 引擎**，需要配置兼容的 Python / IfcOpenShell 环境。下面的免安装说明针对 Windows x64 正式安装包。

## 第一次使用 BIM：按这三步体验

### 1. 检查引擎

在有工作目录的主对话中发送：

> 请实际检查当前会话的 BIM 引擎，告诉我是否可用、正在使用哪个 Python、IfcOpenShell 是什么版本。先只做健康检查，不创建模型。

预期会调用 `bim_engine_health`，返回实际引擎可用状态、解释器路径和版本。Windows 默认应使用安装目录内 `engineering-bim/runtime/python/python.exe`，不是仅用文字回复“支持 BIM”。

### 2. 创建一个简单模型，并明确要求回读和预览

可直接复制：

> 请用 BIM 工具创建一个演示用 IFC4 模型，项目名“BIM 入门演示”。只建一根矩形梁 B1：局部 X、Y、Z 三向尺寸分别为 6、0.3、0.5 米；最小角点位于工程坐标 (0,0,0) 米，绕 Z 轴旋转 0 度。保存为当前工作目录中的新文件 bim-demo-01.ifc；若文件已存在，请使用新的编号，保留旧文件。生成后，将它登记为“生成模型”来源，回读核对尺寸和位置，再生成三维预览与几何体积结果。请给出文件路径、实际工具结果和待复核项。

正常处理顺序是：检查引擎 → 根据明确参数生成新 IFC → 登记生成文件的实际路径和内容指纹 → 回读 → 请求预览和几何量。后面几步仍需智能体调用工具，**生成文件本身不会自动完成来源登记或显示三维视图**，因此示例把这些后续动作一起写明。

对这个无开口的演示矩形体，几何体积应为 `6 × 0.3 × 0.5 = 0.9 m³`。这个数可以用于核对演示流程，不能推广为复杂模型都已验证。

### 3. 查看结果

- 在主对话查看执行结果、文件路径及缺口提示。
- 打开会话的 **“本次任务 → 任务概览”**，或进入已绑定会话的项目工作台，找到 **“工程数据与计算”**。这里查看结果，尺寸和规则的修改继续在主对话中提出。
- 当预览操作实际返回网格后，面板中会显示 **“IFC 几何预览”**：可拖动旋转，使用放大、缩小、复位按钮，并通过下拉框选择构件。
- 面板可显示构件 GlobalId、几何净体积、毛体积、开口扣除量和原生数量属性；具体显示哪些内容取决于实际执行了查询、几何量或预览中的哪些操作。
- **“查看 IFC 文件”不等于自动生成三维预览。** 三维视图来自预览工具返回的真实网格。

工程面板在尚无对象、也无工程运行记录时隐藏。仅上传附件或只登记来源，可能仍看不到该面板；独立引擎健康检查也不等于新增工程运行记录。完成一次工程操作后可点击“刷新工程记录”，正常情况下约每 5 秒自动刷新。

## 分析已有 IFC 模型

先将 `.ifc` 文件放入当前会话工作目录，或把文件交给助手，要求其先确认实际路径并将授权资料放到该工作目录。附件出现在聊天中，不代表文件已经满足 BIM 工具的工作目录要求。

可发送：

> 请分析当前工作目录中的项目.ifc。先登记来源版本，清点模型单位、空间层级和构件类型，再查询梁、板的属性及原生数量。先分批处理前 10 个梁构件，生成几何预览，并分别列出原生数量、几何净量、毛量、开口扣除量及差异。无法处理、尚未读取和单位不明的部分单列；有下一页时明确说明，不把这一批当作全模型完成。

需要继续时可说：

> 继续处理同一模型剩余的梁构件，沿用已登记来源和范围目录，逐批报告覆盖情况；不要重复累计已处理构件。

读 IFC 前，智能体需要登记真实文件及 SHA256，并把本次操作关联到该来源。源文件改变后应重新登记、核查受影响结果并复算，不能继续沿用旧版数量。

### BIM 当前支持什么

| 能力 | 3.8.0 可以做 | 当前边界 |
| --- | --- | --- |
| 模型目录与查询 | 读取 IFC 构件类型、空间层级、单位、属性、GlobalId 和原生数量属性 | 当前读取本地 `.ifc` STEP；不直接读取 RVT、NWD、IFCZIP、DWG 或 PDF |
| 几何量 | 按指定构件计算网格体积、表面积和包围范围；分别记录净量、毛量及开口扣除 | 原生数量与几何量分别保留；失败、未闭合、单位不明和未处理对象保留缺口，不填零；多开口仍需核查重叠及各自扣除 |
| 三维预览 | 展示本次实际返回的构件网格，旋转、缩放、选择构件 | 是分批结果预览，不是全模型编辑器；未返回的构件不会自动出现在视图中 |
| 新建 IFC | 生成 IFC4；支持明确尺寸和位置的矩形梁、板、通用代理构件 | 构件类型为 `IfcBeam`、`IfcSlab`、`IfcBuildingElementProxy`；目前不直接创建柱、墙、任意截面、钢筋节点或完整道路地形模型 |
| 坐标 | 输入建模尺寸与位置使用米；位置是局部最小角点，可绕局部 Z 轴旋转 | 不是中心点定位；读取时报告地理参照信息，但不自动应用地图投影变换 |
| 图纸转模型 | 可结合其他插件读取资料，再把有依据、满足现有生成范围的明确参数用于建模 | 不提供 CAD/PDF 一键完整转 BIM，不自动完成设计、结构验算、钢筋细化或加工批准 |

模型生成成功只表示文件生成，几何计算成功只表示该次计算成功；它们都不等于设计审查、合同计量或施工加工认可。

### 大模型如何处理

当前上限：单个 IFC 输入 256 MiB；查询每批最多 100 个构件；几何计算和预览默认每批 10 个、最多 20 个构件；预览默认三角形预算 20,000，几何默认 50,000，上限均为 50,000，包含开口毛量复核；单次新建最多 200 个构件。引擎默认每次运行 30 秒，配置上限 120 秒，结果输出有 8 MiB 预算。

遇到超时、预算限制或部分构件失败，先按楼层、类型、GlobalId 或更小批次处理，并保留未完成范围。缩小批次不能保证每个复杂构件一定可计算；预算也不是全模型完整性证明。

## 九个新增插件怎么用

正式版默认配置包含下面九个插件。它们共同服务主对话与工程账本，**不是九个独立的一键操作页面**。默认配置注册相关插件与工具，具体执行还取决于引擎、资料、采用规则，以及用户请求和智能体调用。

| 插件 | 在主对话中怎么提出任务 | 能力与边界 |
| --- | --- | --- |
| 工程宿主 `engineering` | “登记这次工程的资料版本、构件范围、采用规则和缺项，后续结果沿用同一份记录。” | 保存来源、对象、规则、覆盖和计算历史，连接本次任务与工作台；账本记录本身不会自动识别图纸或证明全图完整 |
| CAD `engineering-cad` | “先清点这套 DWG/DXF 的布局、图层、块、文字、尺寸和外参，再核查指定范围。” | 结构化读取及嵌套块定位；外参不会自动加载，未知或特殊对象、展开预算不足明确保留。DWG 转换成功不证明专有对象无损，也不等于构件已经全部识别 |
| PDF `engineering-pdf` | “列出图纸页目录和带坐标文字，对排水详图分块高清查看，记录已读及未读区域。” | 页目录、文字坐标、高分辨率局部渲染和分块；没有自动 OCR 或完整钢筋识别。扫描页需视觉核查，渲染成功不等于理解完成 |
| 钢筋 `engineering-rebar` | “按这份完整钢筋料表核算；缺项单列。”或“这是中国平法图，先确定适用规则及项目构造条件，再逐组核算。” | 结构化料表计算与有限平法标注文字解析分路，保存规则版本和分口径结果；不内置完整 G101 自动读图系统，不默认补齐锚固、搭接、弯折及抗震条件 |
| 道路 `engineering-road` | “按提供的桩号和横断面数据计算土方分段体积，保留缺失断面和未覆盖桩号。” | 平均断面法、需要中点断面的棱台法及范围核查；不从平面图推测地形，不自动加入压实、损耗或合同计量系数，不是完整道路 BIM 建模 |
| 土建市政 `engineering-civil` | “按这批有依据的尺寸计算管沟折线长度、结构层量和矩形构件量；完整量与已知部分分列。” | 管沟 2D/3D 折线、平面面积×厚度、无洞矩形实体、明确计数及 PDF 视口比例标定；复杂曲线、洞口和缺失尺寸不推测，比例标定不等于自动量取，当前没有图上点击两点的量尺界面 |
| BIM `engineering-bim` | “检查引擎；读取并预览这个 IFC。”或使用前面的明确参数建模示例 | IFC 目录、查询、几何量、预览和有限参数生成；Windows 内置引擎，具体范围见上文 |
| 中国招投标 `china-tender` | “按项目地区、行业和制度整理招标要求、响应证据与缺口，再比较原始 BOQ 和复算量。” | 适用性建议、要求—证据—响应矩阵、原始清单基线及差异；内置基础法律来源有限，不覆盖全国地方规则，不自动授予资格、执行 CA 签章或向交易平台递交 |
| 工程交付 `engineering-delivery` | “导出本次工程计算书和 Excel，保留来源、算式、未知项、已知部分、规则版本和待复核状态。” | 输出真实 XLSX、CSV、HTML、JSON，关联任务草稿成果；不会把生成文件自动认作已验收成果，可继续通过现有 Office/Univer 查看和处理表格 |

需要管理插件时，进入侧栏 **“插件” → “已安装”**，找到相应组合包，进入详情使用组合包或组件开关；工程包名称通常以 `dsh-agent-pi-engineering` 开头，中国招投标包为 `dsh-agent-pi-china-tender`。依赖工程宿主的插件还需要宿主正常加载。已有项目和计算历史会保留，停用后相关工具可能不可用，历史结果也不代表当前插件仍可执行。

另一个入口 **“设置 → 插件 → 插件列表”** 是只读的已加载清单，不应在里面寻找启停按钮。正式版尊重用户已有的卸载选择，不会在每次启动时强制恢复全部插件。插件依赖缺失、曾被卸载或配置被修改时，应先检查实际加载状态和工具可用性，不能仅凭安装版本号判断全部能力可用。

## 道路、市政、土建及平法的建议工作顺序

1. **先定目的和范围。** 是快速清点、复核某类量、找漏项，还是形成可审阅计算书；明确图号、楼层、桩号和专业。
2. **先建立独立目录。** 对照图纸目录、构件表、设计说明或原始 BOQ 建立应检查范围，不能只用已经识别出的对象证明没有漏项。
3. **再逐项读取。** CAD 结合实体、文字、尺寸、布局和外参；PDF 结合坐标文字与局部高清图。区分已列目录、已读、专业复核、验收。
4. **确认单位、比例和规则。** 对中国平法先提供有合法使用权的适用规则资料及项目条件，核查版本和适用范围后采用；当前需要整理为工具接受的结构化规则和输入，上传图集 PDF 本身不会自动变成完整规则引擎。海外料表也需核对直径、数量、单根长度、单位和适用加工口径。
5. **分范围计算并公开缺口。** 几何量、合同计量、钢筋加工量和采购量分开；缺少条件时计算可核实部分，同时列出无法计算的组或对象。
6. **检查覆盖后导出。** 对照独立范围目录核对未读、未算和待复核项，再导出计算书及表格。补遗或参数变更后复算，保留旧结果供追溯。

道路排水图起步示例：

> 请先清点本项目道路及排水图，按图号、桩号和构造类型建立独立检查目录。第一步只核查管道和排水沟长度，明确采用平面长度还是空间长度；记录源图、尺寸和单位。识别不清、外参缺失、未读详图和未覆盖桩号请单列，不要把这些项目按零量处理。形成初步结果后再和我确认下一步算量范围。

中国平法起步示例：

> 这是中国平法钢筋图，请先列明本次构件范围、图纸采用的图集版本、抗震和材料条件，以及还缺哪些规则或节点资料。我提供的规则资料仅用于本项目核查，请先检查适用性并锁定采用版本，再提取集中标注与原位标注。先完成条件明确的钢筋组，分别列出几何长度、计量长度和加工长度；未知构造参数不要自行补齐。

## 专业化工作台、本次任务和专业深度如何配合

普通单次 IFC 体验可以直接在主对话完成。需要按阶段组织资料和交付时，打开对话顶部 **“专业化工作台”**，选择 **“工程图纸与算量”** 或 **“中国招投标与响应复核”**，再按需要选择 **“升级当前工作／将当前工作升级”** 或 **“新建项目”**；已有项目可选择并继续。资料可通过主对话提供，也可在工作台使用 **“添加资料 → 保存登记”**。登记后进入阶段会话推进；创建项目、登记或预览文件本身不等于已经开始全套分析。

在同一项目绑定的会话中持续补充信息。主对话用于提出目的、纠正条件和决定下一步；“本次任务”用于查看共同任务理解和依据；项目工作台用于查看阶段、待处理事项及工程结果。已有项目保存自己的流程快照，新增插件或模板不会自动把旧项目改成新流程。

“专业深度”建议在正式工程复核时开启，它改变检查要求，不替代工程插件或 IFC 引擎。关闭它也不意味着可以跳过来源、单位、重复项和未知条件检查。它不会单凭一次开关操作自动跑遍所有图纸、补齐缺失规则或完成整个工作台。

工程记录按当前会话或所绑定的项目隔离。如果结果看起来不一致，先确认正在查看同一项目及其关联会话，再刷新。`current` 表示已登记依赖未变，不等于专业审核通过；`stale` 表示依据变化、需要复核或重算，不会自动执行重算；“已有支持证据”也不等于资格或合同结论已经获批。

## 遇到问题时先这样排查

| 现象 | 下一步 |
| --- | --- |
| 助手只解释 BIM，未生成文件 | 明确要求“实际检查引擎并调用 BIM 工具”，给出尺寸、坐标、单位及新文件名；查看是否有真实工具结果和文件路径，不能只凭自然语言承诺判定成功 |
| 看不到工程面板 | 确认同一会话/绑定项目，先完成一次有工程记录的操作；仅上传附件、仅登记来源或独立健康检查时，面板可能仍隐藏 |
| 有 IFC 文件但没有三维视图 | 明确要求登记生成文件来源后调用“预览”；生成、目录和属性查询不自动产生预览网格 |
| 提示引擎不可用 | 先运行健康检查，核对实际 Python 路径；检查插件是否加载、Windows 安装是否完整、是否有旧的外部路径配置覆盖内置引擎 |
| 提示超出工作目录 | 将有授权的 IFC 放入本会话工作目录，再登记来源；输出父目录需已存在 |
| 文件名已存在 | 使用新文件名保存；生成工具拒绝覆盖原模型或已有成果 |
| 超时、输出过大、只出现部分模型 | 缩小构件范围或批次，继续处理剩余分页；保留失败项与未处理范围，不把部分成功当作全模型完成 |
| 换了图纸或模型，旧量仍可见 | 查看版本及待重算状态，要求针对受影响来源复算并重新导出；历史结果会保留 |

进阶配置：BIM 引擎选择顺序为插件 `pythonPath` → 环境变量 `AGENT_PI_BIM_PYTHON_PATH` → 存在的 Windows 随包解释器 → 系统 PATH 的 `python`。外部配置优先于随包引擎；更改后重启应用并重新做健康检查。应用不会在每次运行时自动安装或升级 Python 依赖。Windows 随包已验证组合为 CPython 3.13.7 / IfcOpenShell 0.8.5；macOS/Linux 需要另行准备并核验兼容环境。

## 如何判断一次任务真正完成

至少应能看到实际输出文件、来源版本、处理范围、算式或几何结果，以及未处理和待复核项。对专业交付，还需核查独立范围目录与用户目标是否相符，并由相应专业人员审阅。

3.8.0 已验证实际 Windows 包中的九插件加载、内置 BIM、PDF/CAD 运行库、Office 和隔离冷启动；这不等于任意真实工程图纸都已无漏项，也不等于完整平法钢筋设计、CAD-to-BIM 或招投标合规审查已全自动完成。实现及专项证据见 [行业平台实施、验证与边界](3.8.0-engineering-platform.md)，安装包和源码材料见 [3.8.0 Release](https://github.com/xiangxin2021cn/agent-pi-dsh/releases/tag/v3.8.0)。
