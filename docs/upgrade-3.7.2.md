# 3.7.2 升级核查

基线：稳定版 3.7.1；没有合入 3.7.0-RSI.1。沿用当前产品分支。

## 官方内核

采用 `dsh-v0.1.7-alpha.2` 的发行标签提交 `00102833dfaee1da9f48a3a8eae9d34005a75218`。用户提供的 `10ea83bcc3cf97151710cc96dee3a58d54956a40` 为该版本的版本更新提交。官方子模块保持干净，通过官方 clean/build 生成源文件和产物完整性凭据。

官方更新包括对话滚动和历史翻页、排队消息换行、统一代码块显示、Excel 预览及选区保持、持久 PowerShell 与后台任务唤醒、服务重启后的连接恢复、模型名称搜索和工具文字/图片预算处理。来源：[官方发行说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.2)。

`spill-policy.maxInlineBytes` 改为 `maxInlineTokens`。产品没有覆盖官方默认值；旧 settings 中的非负整数字节预算按官方默认迁移比例四字节对应一个估算 token 向下取整，保留用户已显式设置的新预算。该换算用于旧配置过渡，不声称是任意文本的精确分词结果。

## 附件回归修复

3.7.1 的附件上下文消息仍使用 `source.kind: plugin`，被官方 V4 日志编码器拒绝。alpha.2 没有放宽该校验。本版将产品消息来源改为官方迁移规则对应的 `plugin:tender-host`，同时更新按消息 ID 确认附件投递的逻辑。提示词优化、压缩插件及注入器内嵌 PTC 图片上下文也完成相应来源适配。

消息显示通过原生 keyed slot 的优先级扩展包装原有用户/插入消息组件，仅移除显示副本中的产品事务标记。保留原组件、图片和文件引用、复制、时间及本地化；不改写历史消息，不使用 DOM 文本替换，不补丁修改内核。

Windows 和便携运行时打包流程现在必须运行真实官方 V4 编码/恢复回归，分别覆盖 PDF 与 PDF 加两张图片。此前使用模拟消息事件的单测不能替代这项门禁。

## 保留的能力与边界

保留 Univer Office 0.3.2、CAD、MPXJ 项目计划、资源文件栏、可选 Agent Teams、Codex、专业深度、手动模板和报告技能。普通对话不默认启用投标流程或全部知识库。没有将开发实验功能带入稳定版。

MPP 不直接写回原格式；仍编辑后导出 Project XML，P6 导出 XER / PMXML。没有完整排程计算。此次修复不等于解决微信多图批次、图片过期或跨会话串用问题。

界面验收使用独立 DSH_HOME、合成测试文件和仅监听本机回环地址的模拟模型，不使用用户的真实会话或模型凭据。模拟模型验证提交、图片传递、持久化和显示链路，不证明模型对工程图或 PDF 的理解质量。

开发态浏览器验收已通过：原生上传 PDF 和两张不同图片，模拟端点收到两张原生图片及 PDF 引用；资源文件栏注入 PDF 后，产品事务进入官方模型请求流程；两条路径刷新后均恢复历史，正文不显示事务标记，没有页面异常。验收使用 Chrome 无头模式、1500×1000 视口，未覆盖手机端。

宿主、插件设置和发布门禁回归通过；界面与构建完整性回归中，旧 CAD 测试断言补入已在 3.7.1 存在的项目计划下载分支，槽位测试替身补齐官方订阅接口，上游扩展名解析相关测试使用其 tsx 工具链重跑通过。
