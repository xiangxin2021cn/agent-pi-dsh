# 3.7.2 升级核查

基线：稳定版 3.7.1；没有合入 3.7.0-RSI.1。沿用当前产品分支。

## 官方内核

采用 `dsh-v0.1.7-rc.1` 的发行标签提交 `46a7f68b0922371ce7144b668b90e377d8e799f4`。用户提供的 `a60af51e809d008d89af3ade60ee107547b175bf` 为该版本的版本更新提交。官方子模块保持干净，通过官方 clean/build 生成源文件和产物完整性凭据。

官方更新包括对话滚动和历史翻页、排队消息换行、统一代码块显示、Excel 预览及选区保持、持久 PowerShell 与后台任务唤醒、服务重启后的连接恢复、模型名称搜索和工具文字/图片预算处理。来源：[官方发行说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-rc.1)。

在已准备的 alpha.2 基础上，rc.1 继续带来以下变化（按两次发行标签之间的源码差异核对，避免把官方跨多个版本的汇总全算成新增）：

- 原生工作过程展示增加简洁、标准、详细、完全展开四档。产品保留按用户语言显示的任务状态，撤除旧的二档按钮和强制隐藏/展开样式，统一由“设置 → 通用设置 → 工作步骤展示”控制。
- 工具准备、启动和结果阶段显示更加明确，文件写入/编辑可显示准备进度；聊天图片支持悬停/聚焦预览及展开。
- PDF 缩放结束后重新渲染，表格预览改善触控板双向滚动、工作表切换和深色主题。
- 安装与启动执行插件 peer 版本兼容检查，插件安装进程超时后释放锁，网关取消流的保留数量有界。
- 官方 Office 技能改用 LibreOffice Kit 0.1.0 CLI。打包必须验证对应平台引擎存在；保留独立 Univer 编辑能力及原有许可文件。

预装插件的官方兼容检查中，AnySearch 0.1.6 是唯一被 peer 范围拒绝的第三方包；截至本次核查，上游 npm 最新仍为 0.1.6。保留其安装与用户配置，让官方启动检查决定是否载入，产品默认搜索在其不获允许时选择 `deepseek-official`，避免指向未注册的搜索提供方。用户已主动授予的精确版本豁免仍由官方读取。

不自动添加插件版本豁免，不替换 DSH 原生提示词，不修改官方子模块。旧的产品“执行详情”浏览器本地偏好不再覆盖官方设置；已有官方工作过程偏好继续由官方迁移处理。

`spill-policy.maxInlineBytes` 改为 `maxInlineTokens`。产品没有覆盖官方默认值；旧 settings 中的非负整数字节预算按官方默认迁移比例四字节对应一个估算 token 向下取整，保留用户已显式设置的新预算。该换算用于旧配置过渡，不声称是任意文本的精确分词结果。

## 附件回归修复

3.7.1 的附件上下文消息仍使用 `source.kind: plugin`，被官方 V4 日志编码器拒绝。rc.1 没有放宽该校验。本版将产品消息来源改为官方迁移规则对应的 `plugin:tender-host`，同时更新按消息 ID 确认附件投递的逻辑。提示词优化、压缩插件及注入器内嵌 PTC 图片上下文也完成相应来源适配。

消息显示通过原生 keyed slot 的优先级扩展包装原有用户/插入消息组件，仅移除显示副本中的产品事务标记。保留原组件、图片和文件引用、复制、时间及本地化；不改写历史消息，不使用 DOM 文本替换，不补丁修改内核。

Windows 和便携运行时打包流程现在必须运行真实官方 V4 编码/恢复回归，分别覆盖 PDF 与 PDF 加两张图片。此前使用模拟消息事件的单测不能替代这项门禁。

## 保留的能力与边界

保留 Univer Office 0.3.2、CAD、MPXJ 项目计划、资源文件栏、可选 Agent Teams、Codex、专业深度、手动模板和报告技能。普通对话不默认启用投标流程或全部知识库。没有将开发实验功能带入稳定版。

MPP 不直接写回原格式；仍编辑后导出 Project XML，P6 导出 XER / PMXML。没有完整排程计算。此次修复不等于解决微信多图批次、图片过期或跨会话串用问题。

界面验收使用独立 DSH_HOME、合成测试文件和仅监听本机回环地址的模拟模型，不使用用户的真实会话或模型凭据。模拟模型验证提交、图片传递、持久化和显示链路，不证明模型对工程图或 PDF 的理解质量。

开发态浏览器验收已通过：原生上传 PDF 和两张不同图片，模拟端点收到两张原生图片及 PDF 引用；资源文件栏注入 PDF 后，产品事务进入官方模型请求流程；两条路径刷新后均恢复历史，正文不显示事务标记，没有页面异常。验收使用 Chrome 无头模式、1500×1000 视口，未覆盖手机端。

宿主、插件设置和发布门禁回归通过；界面与构建完整性回归中，旧 CAD 测试断言补入已在 3.7.1 存在的项目计划下载分支，槽位测试替身补齐官方订阅接口，上游扩展名解析相关测试使用其 tsx 工具链重跑通过。

rc.1 增量验证：官方 clean/build 与构建凭据通过；真实 V4 附件编码/恢复、预算迁移、Office 缺失引擎门禁、版本和发布元数据回归通过。打包与实际界面验收单独记录，不能用依赖安装成功替代。

Windows Office 引擎额外核查：上游 0.1.0 在深层 pnpm 路径下发生初始化失败，同一归档放到短路径后成功转换合成 XLSX 为 PDF。Windows staging 将引擎原始字节移至 DSH 的 `node_modules/.office`，用现有相对链接清单恢复引用；不修改上游代码、许可或引擎文件。相应测试覆盖重复运行与安装后链接恢复。
