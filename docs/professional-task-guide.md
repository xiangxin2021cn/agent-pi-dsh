# 专业任务引导

3.7.5 在原生 DSH 执行机制上增加独立 Cordis 插件 `dsh-agent-pi-task-guide`。专业任务从客户目标、项目依据和所选原文件出发；普通清晰小任务无需填写完整表单或先创建工作台。

在已开始的主对话顶部选择“本次任务”页签，默认展示自动积累的任务概览；用户在主对话中表达目标、补充资料、纠正理解和作出决策。任务内容在主对话区域内展示，不改变右侧文件/预览栏宽度。需要精确修正时，可修改目标、范围、受众、专业、交付格式及语言、期限、项目国别与合同及计量依据。公共尽调默认允许，用户可改为需要询问或仅使用已提供资料。修改后使用“保存修正”；有并发修改时保留字段草稿并提示冲突。

“执行计划”展示依赖、进度、缺口、补足方式和源文件覆盖。“可用能力”读取当前会话的真实工具、技能及插件贡献；可用仍需评估具体任务适用性。专业模块未启用或工具不可用时，智能体应采用已有适用工具或明确补足需求。“交付检查”展示实际文件、内容和格式检查、专业复核、签署及客户验收。模型不能替客户确认验收或签署。

3.7.9 将工作台实际资料、模型发现、阶段门禁、项目用户要求及磁盘成果投影到同一份专业任务记录。主对话摘要、“本次任务”和专业化工作台通过原生事件及状态读取联动；切换页签和主执行引擎仍保留当前主会话与绑定项目。工具创建或绑定项目后，当前轮立即启用该项目的实际工具。子任务继承真实主会话绑定，按编号合并证据、覆盖和发现，不能修改主目标或批准阶段。

工作台阶段及人工门禁与执行者登记进度分别展示。模型把工作项标为完成，不能代替实际阶段完成、用户批准或客户验收。资料分母来自项目登记的原始文件，解析稿与对应原稿归并；源文件或解析依据不完整时保留缺口，文本已抽取不等于专业复核。审计问题按类型汇总，保留数量、代表项和完整审计文件出处。

整原稿专业复核需明确登记，并绑定原稿当前 SHA。页面、表格及解析稿的 reviewed 只证明其自身已复核，不能自动增加整原稿已复核数量。主执行者可更新既有工作台原稿覆盖记录的 review 字段，其文件身份、路径、版本及抽取状态由宿主维护；源版本变化后重新待复核。

主执行者可为工作台实际成果补充专业、要求覆盖、计算及格式复核，并关联要求、证据和工作项。文件身份、路径、实际字节检查及用户验收仍由宿主维护，子任务不能覆盖这些成果记录。刷新保留当前版本的专业检查；文件字节变化后，成果检查和依赖阶段转为待复核，旧批准保留为历史，不能用于批准新版本。任务投影以只读方式核对阶段依据，不写入项目阶段或批准记录。

明确的主对话阶段决策与工作台审批使用同一条主机会话准入路径。例如当前处于投标决策阶段时，用户原话“确定投标，按计划推进”会关联真实消息编号、当前项目阶段与依据指纹，在实际门禁通过后登记批准。模型重述、通用“好的”、运行权限批准和网络单价授权不构成阶段批准。系统生成的阶段启动消息仅在主机提前登记、当前会话完全匹配时作为控制消息处理，不覆盖最新用户意图。来源和成果变更仍需复核，读取状态本身不会使审批失效。

投标任务按以下依赖推进，并可仅执行客户委托的其中一部分：

1. 逐文件、页、表、图、附件和补遗解析，登记不可读及缺失单元；从原文定位提取条件、评分点、BOQ 和必交表单。
2. 依据国别、地点、业主、采购及资金体系、合同和规范版本尽调；来源记录 URL、日期、适用范围。公开数据不能替代项目地质、投标企业能力或正式供应商回价。
3. BOQ 每项关联计量范围、工法工效、单位资源消耗、价格和计算；传递金额与实物资源分别处理，资源总消耗与排程峰值分别计算。
4. 从工作包、资源、条件及进度形成实施策划，按实际支付与商业条件计算现金流。
5. 根据实际递交清单和评分点派生专业报告、声明、资格、承诺、偏差、人员设备表格等，逐要求复核并确认签署。

图纸及工程量任务保留图号、版本、位置、构件、尺寸、公式和数量联系；文字抽取不能证明图形几何准确。方案要求项目步骤、资源、参数、检验和异常处理。专业写作预设自动加入上下文，要求准确术语、真实数字、可执行内容；不能仅靠删词或生成文件判定专业质量。

专业判断以准确性及可核验依据为先。对影响投标、计算或实施决策的实质性反证，应说明依据、影响及处理；判断随证据修正，不为附和客户补造事实，也不为争辩而争辩。资料事实及核验状态、计算、推断、行业惯例、框架假设和缺口分别处理。模型记忆及行业惯例可作为查证线索，不能作为已经核实的本项目依据；法规、规范、合同及价格须核对属地、版本、生效时间、范围和补遗。计算正确不代表输入已核实，框架结论限于假设成立的条件，事后解释不能冒充已经验证的预测。关键问题未知时先说明无法判断及缺少的依据，局部缺口在对应结论处明示。发现错误后说明修正，并复核受影响的计算、计划及文件。

上述原则吸收证据分层、反谄媚和主动纠错思想。核验表及内部审校可使用分类；正式客户报告及回标文件沿用行业格式、业主目录及客户语言，不默认逐句添加标签或在末尾附规则自查。置信表达采用核验状态、适用限制和敏感性说明，不生成未经校准的百分比。现有专业任务账本与原生执行机制继续承载事实、推导、假设、冲突及修订，不新增另一套核验状态。

任务保存在 `DSH_HOME/agent-pi/professional-tasks`，按会话隔离。任务修订保留源事实、核验事实、推导、假设及冲突的区别；上游依据变更会让相关下游证据、计划与成果待复核。原有工作台项目快照及显式专业深度设置保留。

第三方 Cordis 插件可选注入 `professionalCapabilities`，用 `scope.effect(() => service.register(capability))` 登记带归属、版本、专业、工具技能要求、国别/规范适用范围、输入输出、限制和补足措施的能力。释放作用域撤销贡献；用户 JSON 工作台是流程声明，由工作台插件承载，不直接执行 JSON 中的代码。接口及类型见 `bundles/task-guide/src/api.ts`。
