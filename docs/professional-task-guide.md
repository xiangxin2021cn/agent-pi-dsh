# 专业任务引导

3.7.5 在原生 DSH 执行机制上增加独立 Cordis 插件 `dsh-agent-pi-task-guide`。专业任务从客户目标、项目依据和所选原文件出发；普通清晰小任务无需填写完整表单或先创建工作台。

在已开始的主对话顶部选择“本次任务”页签，任务内容在主对话区域内展示，不创建右侧抽屉或改变右侧文件/预览栏宽度。可查看和修改目标、范围、专业、交付格式及语言、期限、项目国别与合同及计量依据，回答智能体登记的关键问题。公共尽调默认允许，用户可改为需要询问或仅使用已提供资料。修改后使用“保存需求”；有并发修改时读取最新状态后再保存。

“执行计划”展示依赖、进度、缺口、补足方式和源文件覆盖。“可用能力”读取当前会话的真实工具、技能及插件贡献；可用仍需评估具体任务适用性。专业模块未启用或工具不可用时，智能体应采用已有适用工具或明确补足需求。“交付检查”展示实际文件、内容和格式检查、专业复核、签署及客户验收。模型不能替客户确认验收或签署。

投标任务按以下依赖推进，并可仅执行客户委托的其中一部分：

1. 逐文件、页、表、图、附件和补遗解析，登记不可读及缺失单元；从原文定位提取条件、评分点、BOQ 和必交表单。
2. 依据国别、地点、业主、采购及资金体系、合同和规范版本尽调；来源记录 URL、日期、适用范围。公开数据不能替代项目地质、投标企业能力或正式供应商回价。
3. BOQ 每项关联计量范围、工法工效、单位资源消耗、价格和计算；传递金额与实物资源分别处理，资源总消耗与排程峰值分别计算。
4. 从工作包、资源、条件及进度形成实施策划，按实际支付与商业条件计算现金流。
5. 根据实际递交清单和评分点派生专业报告、声明、资格、承诺、偏差、人员设备表格等，逐要求复核并确认签署。

图纸及工程量任务保留图号、版本、位置、构件、尺寸、公式和数量联系；文字抽取不能证明图形几何准确。方案要求项目步骤、资源、参数、检验和异常处理。专业写作预设自动加入上下文，要求准确术语、真实数字、可执行内容；不能仅靠删词或生成文件判定专业质量。

任务保存在 `DSH_HOME/agent-pi/professional-tasks`，按会话隔离。任务修订保留源事实、核验事实、推导、假设及冲突的区别；上游依据变更会让相关下游证据、计划与成果待复核。原有工作台项目快照及显式专业深度设置保留。

第三方 Cordis 插件可选注入 `professionalCapabilities`，用 `scope.effect(() => service.register(capability))` 登记带归属、版本、专业、工具技能要求、国别/规范适用范围、输入输出、限制和补足措施的能力。释放作用域撤销贡献；用户 JSON 工作台是流程声明，由工作台插件承载，不直接执行 JSON 中的代码。接口及类型见 `bundles/task-guide/src/api.ts`。
