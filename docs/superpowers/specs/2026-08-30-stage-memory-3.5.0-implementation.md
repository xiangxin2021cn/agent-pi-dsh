# Agent Pi DSH 3.5.0 阶段记忆实施规格

## 目标

投标长程创作的权威状态必须在项目磁盘上，而不是依赖主对话是否仍保留上一阶段全文。上一阶段完成后形成可校验 handoff；下一阶段声明自己消费哪些 handoff 和能力包。聊天压缩只压缩沟通历史，不改变业务基线。

## 存储与事务边界

- 路径：`.agent-pi/business/<module>/<projectId>/orchestration/handoffs/<stageId>/vNNNNNN-<digest>.json`。
- handoff 只追加、不覆盖；同目录临时文件写完后原子 rename。
- 包含项目/阶段标识、修订号、输入 handoff/能力包状态、正式成果路径/大小/mtime/SHA-256、能力包修订、人工审批、已接受用户要求、有限长度状态胶囊。
- 阶段状态只能在 handoff 校验并写入成功后提交为 `done`。人工门仅在用户批准后提交。

## 依赖与失效

- `WorkflowStage.consumes` 是唯一机器依赖图；handoff 依赖默认必需，能力包另由既有阶段硬门确保可用并在 handoff 中记录实际版本。
- Official Outputs、登记源文件、能力包、审批、用户变更要求或阶段重置改变基线时，追加失效事件。
- 失效范围是源阶段加 `consumes` 的传递闭包；无依赖阶段保持有效。
- 失效阶段回到 `blocked`，清除旧 `completedAt`、审批和 dispatch；磁盘成果保留供差异修订。

## 上下文预算

- 每轮动态 `agent-pi:project-memory` 上下文上限 12,000 字符。
- 最多展开当前阶段直接消费的 4 个 handoff，每个胶囊最多 1,800 字符；精确事实通过 handoff 的成果路径回读。
- 单个 handoff 胶囊最多 8,000 字符；大文件只记录哈希和路径，不进入 prompt。
- 项目事实只写项目 handoff；全局知识库只存通用规范/范文；skill/模块只沉淀用户明确验收的方法。

## 恢复语义

- 重启：从版本文件和失效事件重建快照，不依赖进程内缓存。
- 压缩：DSH 重新组装 system context 时重新读取项目快照；压缩摘要不是业务事实源。
- 外部编辑：工作台盘点按 stat 快路径和必要时 SHA-256 检测漂移，随后精准失效。
- 旧项目：盘点时按工作流顺序补建可验证 handoff；无法满足输入的阶段明确阻塞。

## 验收

- 不可变写入、schema/digest 校验、同基线幂等。
- 冻结组价基准变化只失效组价、策划和最终提交链，不失效已完成的招标分析。
- 工作台显示基线版本、前序版本、待生成/失效状态；保存或删除前显示影响范围。
- 24 MB（约 600 万 token 风格）输入不进入动态 prompt；重启和压缩后仍能从 handoff 路径恢复。
- DSH 官方子模块保持 `cd5ef81481` 字节干净。
