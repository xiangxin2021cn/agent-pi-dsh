# Agent Pi DSH 3.3.5 Integration and Cross-Platform Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate the approved Codex, capacity, and compaction changes into the existing 3.3.5 line, rebuild and smoke-test the Windows installer, upload the runtime payload, trigger the real macOS/Linux workflow, and verify a complete GitHub 3.3.5 release.

**Architecture:** Treat the three feature plans as separately verified commits, then run one integration gate before packaging. The Windows publishing script uploads the installer plus runtime payload and invokes the repository's existing `build-desktop-assets.yml` workflow with the same tag; GitHub-hosted runners create the non-Windows assets from that payload.

**Tech Stack:** Bun/Node test runners, Electron Builder/NSIS, PowerShell, GitHub CLI and Actions, runtime payload tarball plus SHA-256 manifest.

**Spec:** `docs/superpowers/specs/2026-08-28-codex-context-compaction-design.md`

## Global Constraints

- Release and application version remain exactly `3.3.5`; tag remains `v3.3.5`.
- Do not create or publish `3.3.6`.
- Do not delete or overwrite unrelated release assets.
- Use `--clobber` only for the exact 3.3.5 assets rebuilt by this plan.
- GitHub writes require the `github:yeet` skill immediately before publishing.
- A successful Windows upload is not completion; macOS and Linux workflow results and final asset names must be verified.
- Preserve unrelated working-tree changes and the nested DSH checkout.
- Before any completion claim, use `superpowers:verification-before-completion`.
