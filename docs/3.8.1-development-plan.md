# Agent Pi DSH 3.8.1 改造方案

本版把投标文件中的要求和评审标准连接到响应计划、企业材料、专业计算、成稿和复核。用户继续在主对话中表达目标；本次任务与专业工作台读取相同记录。版本为 3.8.1，沿用当前分支，保留 3.8.0 的九个工程插件、开箱即用 Windows BIM 和完整 Univer Office。

## 基线与范围

- 开发基线：`30935c2`，应用 3.8.0；开发开始时发布工作树干净。
- 已有 `TenderEvaluationCriterion`、`TenderResponsePlan`、评分策略校验、企业知识版本、专业任务状态、工程依赖与 Office 交付检查，优先扩展这些机制。
- 中国插件已有制度适用和证据响应，但工作流缺少明确的技术标编写阶段。其要求须与通用响应模型关联，避免各维护一套评分台账。
- Skill 定义操作方法；项目事实和状态保存到结构化项目记录；代码负责可确定的约束检查。正文专业含义和材料真实性仍需有依据的审阅。
- 本轮交付详细方案、实现、自动化与界面验证、使用说明、发布说明、本地 Windows 安装包及回执。不覆盖 3.8.0 资产；GitHub 发布作为单独动作。

## 用户流程

1. 用户选择本项目资料，在主对话提出技术标目标；系统先读取任务、资料与当前工作流。
2. 依据实际文件和补遗提取资格、实质性条件、评分项、格式及递交要求，保留原文位置和未读文件/页面。
3. 系统建立响应计划：每章回应什么、使用哪些企业材料、需要哪些工程事实和计算、缺什么。
4. 项目强制目录直接遵循；仅对影响范围、承诺、资料优先关系的歧义向用户澄清。
5. 根据计划引用原件、调整可复用内容、生成项目章节；CAD、算量、BIM 等成果通过实际依据参与。
6. 检查当前成稿中的响应位置、来源和文件版本，区分机器检查、内容审阅与人工决定。
7. 补遗、材料或计算变化后，将受影响的响应标记为待复核；无关内容继续使用。

## 数据与实现

### 评分细则及章节

- 扩展现有评分项的可选细则，保留评分原文、子点、分档条件和出处。旧项目不要求补齐新字段才能打开。
- 在现有 response 上增加可选章节计划：稳定章节标识、生成方式、必答子点、材料引用、工程依据、实际文件及定位。
- 通过/不通过项不设置目标分；内部建议不能冒充招标文件的正式评分规则；覆盖情况不能称为最终得分。
- 一个评分点可对应多个章节，一个章节可回应多项要求；保留既有 requirement/criterion/deliverable ID。

### 材料使用

- 复用现有知识版本机制，不复制企业知识库。
- 响应计划记录所选材料的主体、用途、适用条件、有效期和授权/可用性核验结果。
- 原件引用：保持证书、证明事实及附件原貌；条件化复用：明确适用条件及改写范围；项目生成：使用当前资料、数量、资源和工期。
- 未核验、过期、错主体或未确定投入的材料保持缺口，模型不能自行改成已核验。

### 成稿与变更

- 为章节绑定实际文件版本和可核对位置；主文可保留结构化节点，渲染后的页码只属于该文件版本。
- 确定性检查覆盖文件存在、当前哈希、定位内容、引用关系及必答点；存在关键词不能证明专业语义充分。
- 人工/专业复核记录须有对象、依据、时点和说明，不能仅根据文件存在自动通过。
- 记录响应所依赖的条款、证据和计算；对来源修订做逐响应检查。兼容现有较粗的 capability 失效机制，不伪称所有旧包已获得精细失效能力。
- 账本、能力包和复核调用显式绑定模块及项目编号；中国与原投标模块同名不串用数据。中国资料同步传播已登记来源的明确失效状态，空要求批次也可同步，未出现的来源不推断为撤回。

### 模板与插件联动

- 区分项目强制格式、用户明确采用的格式、企业参考样稿；历史样稿不强制复制章节数。
- 通用投标方法继续通过现有工具执行；中国工作流加入响应策划、正文编写及逐项复核，并复用通用记录。
- 道路、市政、土建、钢筋、CAD、PDF、BIM 提供专业事实。非工程写作不强制要求 BOQ，工程分析仅按实际范围启用。
- 专业深度调整审阅强度，基础来源、有效性、必答项检查始终保留。

## 界面

- 专业工作台增加响应对照：要求/评分项、原文、章节、材料与计算、成稿状态、缺口，支持定位原文与成果。
- 本次任务展示同源摘要及待处理事项；主对话呈现关键影响与问题，避免批量填写表单。
- 无数据时显示下一步；读取失败显示可重试原因；刷新、切换会话不沿用其他项目数据。
- 进度区分要求识别、计划覆盖、正文形成、证据准备、复核完成。未覆盖资料独立展示，不能因已登记条目全部响应而宣称整个标书完成。

## 核心插件更新

1. 从本仓库 pin、插件来源和锁文件列出当前 DSH 与核心插件，不将本应用插件版本号调整称为上游升级。
2. 核查官方仓库、发布标签或包注册表，记录版本、提交、核查时点与兼容性。
3. 有可兼容更新时更新 pin、物化源码/依赖及必要补丁，并执行相关插件和宿主回归。
4. 没有更新或存在明确不兼容时记录原因，保留可用版本；不删除 Office、工程能力或授权检查来换取构建通过。
5. DSH 若更新，遵循内核版本历史、完整来源和构建回执要求；本版版本提升满足 pin 变更的应用版本约束。

## 分工与顺序

1. 先保存本方案并确认接口：通用模型与检查、宿主 API、界面读取使用一份契约。
2. 并行实施通用响应模型与审计、响应对照界面、核心插件升级；主执行负责中国工作流、工具接入、Skill、版本及说明。
3. 集成同源状态与实际文件检查，完成真实边界条件的测试，再进行浏览器操作验证。
4. 完成升级说明、使用指南及已验证能力边界，核对差异后生成本地版本提交和标签，按原流程构建安装包。
5. 对实际安装包载荷进行冷启动、插件加载、BIM/Office 和新流程烟测，生成校验和及构建回执。保持生产用户项目不受测试污染。

## 验收

| 场景 | 必须满足 |
| --- | --- |
| 旧项目 | 3.8.0 数据可读取；无新字段显示未规划，不虚构已完成 |
| 评分细则 | 漏子点、错误引用、否决项目标分等能被检查；原文等级不被改写为承诺分数 |
| 章节计划 | 要求与章节可多对多对应；强制目录优先；历史模板不会机械生成无关章节 |
| 企业材料 | 过期、错主体、未核验/未授权材料保持缺口；原件事实不被改写 |
| 工程依据 | 可引用实际 CAD/数量/BIM/资源成果；未读图纸和缺参数不会自动消失 |
| 成稿反查 | 缺文件、内容位置不符、成稿修改、来源修改使对应响应待检查；机器检查不冒充语义审阅 |
| 局部变化 | 一项补遗影响对应章节；未依赖该变化的章节不无故变更 |
| 中国路线 | 工作台可到达技术标策划与编写，同一响应记录可在主对话/任务/工作台查看 |
| UI | 空态、已规划、缺证据、已生成、待复核可辨；原文与成果跳转；切换会话和刷新无串项 |
| 插件 | 核查并记录上游更新，实际包与 pin 一致，Office 和工程插件仍可加载 |
| 包装 | 应用/安装器均为 3.8.1；真实载荷可冷启动；安装包、校验和和回执一致 |

本方案中的验收条目是本版目标。最终完成情况及限制以 3.8.1 使用说明、升级说明和验证记录为准；不以生成页数、模型自评分或模拟中标概率代替验收。
