# Agent Pi 产品界面翻译审计

范围：共享产品客户端的十种界面语言与本次工作台自主编辑功能。DSH 上游客户端、第三方 Office/CAD 插件各自维护的词条不纳入本表；用户编写的流程、报告及知识内容不会被自动改写。

## 结论

此前除中英文外，其他八种语言仅有 32 项产品词条。存在大量英文回退，以及专业深度、文件预览和工作台业务页面里的硬编码中文，不能称为完整多语言支持。

本次将词库从客户端主文件分离，补齐工作台阶段编辑的核心字段、依赖错误和保存/删除确认；统一“专业工作台”与“文件工作目录”等含义。其他页面缺口已定位，没有把回退英文计为已翻译。

| 语言 | 修改前词库覆盖 | 当前词库覆盖 | 仍缺词条 |
| --- | --- | --- | --- |
| 中文、英文 | 各 318/318 | 各 329/329 | 0 |
| 西班牙语、法语、德语、日语、韩语、葡萄牙语、俄语、阿拉伯语 | 各 32/318 | 各 105/329 | 各 224 |

这是词库覆盖率，不是整个应用界面的完成率。中英文词库齐全也不代表词库外的中文常量已有对应英文。八种语言当前各约 32% 的产品词库覆盖，尚有明显缺口。

## 专业术语原则

| 中文概念 | 英文基准 | 处理 |
| --- | --- | --- |
| 专业工作台 | Workbench | 表达专业操作界面，不与工作目录混用 |
| 工作目录 | Working directory | 指本地文件路径，不译成业务工作台 |
| 阶段依赖 | Prerequisite stages | 表达必须先完成的阶段，不等同一般“关联” |
| 人工审批 | Human approval | 用户决定，不能译成模型自动检查 |
| 复核范围 | Review scope | 区分全量复核与风险、变更、抽样复核 |
| 项目实施控制 | Project controls | 避免误译为快递、文件发送或普通交付 |
| 投标校验 | Tender validation | 保留采购投标语义，避免一律解释成报价 |
| 知识库资料 | Knowledge sources | 用户指定的资料来源，不能暗示系统自动读取全部记忆 |

阶段名称允许用户使用当前语言。阿拉伯语沿用现有 RTL 方向设置；文件栏及工作台边距改为逻辑方向，修复与原生侧栏的遮挡，拖拽宽度也跟随方向。窄窗口打开工作台时暂收起文件栏，退出工作台即恢复。路径、模块标识和技能标识仍是原值。各语种术语是本次代码内翻译，尚未经过每个语种母语领域专家校订。

## 待继续治理的区域

1. 文件预览、专业深度、项目计划和团队设置仍有散落的中文展示文案。
2. 工作台业务执行、附件与知识库页面的其余词条仍需逐页翻译；缺失项回退英文。
3. 内置业务流程的默认名称、专业说明及后端校验错误并未全部国际化。它们不能简单计入 UI 短词条翻译率。
4. 对话辅助设计目前部分预设指令仍为中文，需与用户任务内容的语言边界一起处理。
5. 专业术语需按实际界面上下文复核，不能仅按字面批量替换。

按含汉字的源码行生成候选列表，可能包含注释、示例和发给模型的指令，**不能将候选行数当成未翻译控件数**。

## 可重复检查

```powershell
node scripts/audit-product-locales.mjs .codex-temp/i18n-audit.json
node --test bundles/tender-web/tests/locales.test.mjs
```

审计脚本列出每种语言缺失的词条、占位符差异以及词库外含中文的源码行；占位符丢失会返回失败。测试覆盖本次编辑器核心字段在全部十种语言中存在、插值参数一致、工作台与工作目录不混淆。全量列表由脚本产生，避免报告与实际源码长期脱节。

实机浏览器检查：Chrome，英文和阿拉伯语，1500×1000 / 430×932；编辑器无横向溢出，左右书写方向下的文件栏宽度拖拽均正常，无页面脚本异常。此项不是其余六种语言的逐屏人工验收。
