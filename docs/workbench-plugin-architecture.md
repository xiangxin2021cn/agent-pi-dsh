# 用户自主工作台与 DSH 插件架构

适用版本：3.7.4，基于 DSH 0.1.7-rc.2。

## 用户可以直接做什么

入口：**专业化工作台 → 模块管理 → 自己新建工作台**。

- 新建工作台，或将内置工作台复制为自己的版本。
- 编辑名称、阶段要求、阶段顺序和前置依赖；增删阶段。
- 指定执行技能、复核技能、复核范围、人工审批节点及成果报告要求。
- 自主选择知识库资料；新建自定义流程不默认加载任何知识包。
- 启停模块，导出流程 JSON，导入后继续编辑；删除自己的模块。
- 如需帮助，可展开“对话辅助设计”。直接编辑不创建对话、不调用模型。

名称可以用用户自己的语言；内部模块和阶段标识目前仍需小写拉丁字母、数字和连字符。技能字段目前填写已安装技能的标识，并非图形化技能市场。此版提供流程和功能配置，不包含任意拖放面板、编写前端组件的低代码画布。

内置模块保留为模板，修改时先复制。投标副本默认保留内置硬性校验；用户可以明确转为“自定义流程”，解除投标专属校验和能力依赖。已有人工审批节点保留，用户可以继续编辑。

## 变更与数据边界

保存定义后，新项目使用新流程；既有项目使用创建时的流程快照，避免阶段、成果、审批记录突然错位。当前不提供进行中项目的任意流程迁移。

改名阶段时同步调整引用；被其他阶段依赖的阶段须先解除依赖才能删除。移动阶段不能让前置阶段排到其后面。编辑器保存携带版本摘要，另一窗口修改过后要求重载，避免覆盖他人或自己的新修改。

用户定义保存在 `DSH_HOME/workbench/modules`，不写回程序安装目录。删除用户定义时保留历史版本及项目数据。旧用户项目通过保留的历史定义读取；没有快照的旧内置项目使用随应用保留的内置定义读取。不能凭空恢复本次升级前已被外部删除的用户定义。

模块停用后拒绝新项目及阶段执行入口，既有项目仍可查看。停用不是取消已经开始的模型任务；中止当前任务仍使用 DSH 原生停止操作。模块卸载不删除成果、知识库或对话。

## 原生插件分工

| 包 | 职责 | 停用影响 |
| --- | --- | --- |
| dsh-agent-pi-workbench | 工作台服务、模块与项目管理、阶段工具、项目上下文及工作台 HTTP 路由 | 移除工作台入口、相关工具、提示扩展和路由 |
| dsh-agent-pi-workbench-tender | 投标流程及投标领域工具 | 移除投标供给；依赖其校验的副本不能执行 |
| dsh-agent-pi-workbench-delivery | 项目实施控制流程 | 移除该流程供给 |
| dsh-agent-pi-workbench-investment | 投资研究流程 | 移除该流程供给 |
| dsh-agent-pi-knowledge | 知识库工具、路由、显式选择资料的上下文 | 知识库入口和注入停止；本地资料保留 |
| dsh-tender-host / dsh-tender-web | 现有桌面适配及共享界面、附件、文件栏、Office/CAD/项目计划等能力 | 本次保留其兼容入口 |

使用 Cordis 原生 `provide/inject/effect` 管理依赖和释放。HTTP 注册返回的释放函数显式加入插件作用域，避免热重载遗留路由。普通会话不因工作目录存在项目而自动启用业务工作流。

工作台服务按 DSH 上下文隔离，贡献由安装它的插件持有。共享业务实现仍位于原有源码目录，未复制成多个实现，也未修改 DSH 内核。前端暂由共享客户端渲染，通过能力状态隐藏已卸载功能；不是每个领域都重新打包一份前端。能力状态在窗口聚焦及每 5 秒刷新。

原生插件管理负责安装/卸载代码插件，工作台内的模块管理负责停用或编辑流程。首次升级补齐这五个产品插件，之后再次初始化不恢复用户主动卸载的插件。原生 profile 中用户保存的禁用设置继续有效。

## 开发者扩展入口

独立 DSH 包可声明 bundle patch，注入 `workbench` 服务并注册流程。例如：

```ts
import type { WorkbenchRegistry } from 'dsh-agent-pi-workbench/api'

export const name = 'example-inspection'
export const inject = ['workbench']

export function apply(ctx: {
  workbench: WorkbenchRegistry
  effect: (install: () => () => void) => unknown
}) {
  ctx.effect(() => ctx.workbench.registerModule({
    owner: 'dsh-example-inspection',
    workflow: {
      id: 'inspection-main',
      module: 'inspection',
      label: 'Site inspection',
      labelZh: '现场检查',
      kbPack: { analysis: [], pricing: [], planning: [] },
      stages: [{
        id: 'inspection-report',
        label: 'Inspection report',
        labelZh: '检查报告',
        hintZh: '使用本项目指定资料',
        prompt: '核对用户指定的现场照片，区分事实与待核实事项，交付检查报告。',
        skillSlugs: [],
      }],
    },
  }))
}
```

包的 `dsh.bundle.patch` 指向插入该插件的 Cordis patch；沿用 DSH 原生安装与兼容性检查。工作台 API 当前为版本 1。插件名和模块标识不得与已有贡献冲突；重复注册直接拒绝。新增领域工具须由插件通过 DSH 原生工具服务注册，不会仅凭 JSON 定义获得执行代码能力。

此 API 属于 Agent Pi 产品扩展，依赖已安装的工作台核心插件。停用核心后，依赖它的领域插件由 Cordis 管理失活；重新启用时恢复。工具历史名称 `tender_stage` 暂保留以兼容旧会话，自定义工作台使用通用任务规则。

## 验证与已知范围

- 主机与客户端 490 项回归测试全部通过，覆盖工作台、项目快照、依赖校验、插件作用域、附件、Univer/CAD 和现有文件交付等代码路径；客户端构建及 Git 空白检查通过。
- 隔离 DSH profile 冷启动与真实 Chrome 操作验证：新建两阶段流程、重命名依赖、阻止非法删除/排序、保存重载、旧项目快照保留。
- 原生 profile 热停用知识库和工作台：相应 API 返回 404、侧栏入口消失；通用文件 API 仍可用。恢复后无重复路由。
- 英文、阿拉伯语在 1500×1000 和 430×932 Chrome 窗口验证通过；工作台内容无横向溢出，无页面脚本错误，文件栏拖拽在两种方向下均正确。中文已验证完整创建、修改和保存流程。
- 开发验证没有调用付费模型完成真实业务任务，也没有重装用户应用或迁移生产数据。安装包按公开发布流程另行生成并验证。回归测试通过不等于全部 Office/CAD 二进制格式均已重新人工验收。
- 现有 AnySearch 0.1.6 声明的 DSH 兼容范围不含 0.1.7-rc.2，启动器继续按官方规则跳过；本次不绕过兼容性校验。
