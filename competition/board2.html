核心流程：一次长程任务，从标书到标稿 WORKFLOW
01

标书全量解析，规范入库

一次任务读完所有标书文件；规范、FIDIC 条款进入本地知识库，与特别条款修订逐条对照总结——过程材料全程不丢，产出详细分析文档。

02

数千条 BOQ，逐项界定范围

庞大 BOQ 清单逐条引用规范、标书特别条款、FIDIC 修订，为每一个条目界定工作范围——不靠印象，每条都有出处芯片。

03

五步推导，算出每条单价

依据工作范围，结合企业数据与网络验证的工法、工效、资源实时实地价格，对每条 BOQ 做详尽的五步推导。

04

资源汇总与成本推定

所有推导汇总成资源清单与成本推定，带公式的 BOQ 组价测算表可直接改——施工组织策划可验证的最坚实基础。

05

按项目特征施工推演

根据标书文件的项目特征进行施工推演，建立一整套可执行的施工策划稿，不是空话套话。

06

照企业模板编制标稿

依照企业常用投标格式与内容深度模板编制投标文档——用户模板复刻版式、大纲与深度，项目事实永远来自本项目资料。

三个深思熟虑的架构决策 DESIGN DECISIONS
决策 01

知识库不堆 RAG普通电脑就跑得动

一套像样的 RAG 要嵌入模型、向量库、GPU 与 Docker 编排——太重、用不起；且向量检索是「相似度猜测」，检索到 ≠ 证据对。本系统按文档自身章 / 节 / 条切分条款，MiniSearch BM25 检索：零重型依赖，每条命中精确定位到 Clause，出处当场可核。

决策 02

百万上下文任务全程不失忆

DeepSeek V4 全系支持 1M tokens 上下文（约 800 页 PDF）——整套标书、规范、数千条 BOQ 与全部中间稿全程驻留上下文。模型不靠检索「猜」该看什么，而是在完整事实面前工作：任务始终围绕目标推进，不因截断而偏离。

决策 03

换到 DSH 架构实测优于双架构

全程跑下来最难的 BOQ 逐条分析，DeepSeek Harness 架构运行效果明显优于 Claude Agent SDK + Pi 双架构——内核原生并行工人、持久 Bash 不再卡顿、长任务崩溃只救未完工部分。3.0 果断换芯：回合更短、token 更省、目标更稳。

BOQ 五步推导详解 FIVE-STEP PRICING
1

范围界定

逐条引用规范、特别条款、FIDIC 修订，界定每条 BOQ 的工作范围。

2

工法选定

结合企业历史数据与网络验证的成熟工法，确定施工方案。

3

工效测定

按工法与项目条件测定人工、机械工效，过程留痕可复核。

4

资源取价

资源实时实地价格：当地人工、材料、设备、运输逐一取定。

5

单价合成

五步合成单价并汇总成本推定，带公式测算表可直接改。

知识库与证据链 KNOWLEDGE & EVIDENCE

证据链：引用是出处，不是摘抄

  • 证据门禁：项目特征缺口不能用模型记忆填——要么找到出处，要么由人尽调后授权放行，基本杜绝幻觉；
  • 出处芯片：稿中引用只显示源文件、页或行、题目或段落，点击即达原文；证据正文绝不贴进正式稿；
  • 成果落盘：统一成果树写回项目目录，崩溃重启不重做；正式稿上的人工修改留在原处；
  • 规范即检索：规范、合同、图纸说明按自身章节切条入库，BOQ 每一行都能回指到具体条款。
对企业生产力的解放：同样的标一旦中标，投标阶段的全部详尽基础资料直接服务实施阶段——成本策划有据可依，落地即有据可查。
