# Agent Pi DSH 3.5.0 — 投标阶段记忆与可恢复长程创作

3.5.0 把“上一阶段成果服务下一阶段”从提示词约定升级为磁盘上的业务事务。每个阶段收口前先校验输入、正式成果、能力包和用户决策，再原子提交不可变 `StageMemory/Handoff`；聊天记录和压缩摘要不再承担投标基线职责。DeepSeek Harness 仍固定在 **`dsh-v0.1.2-alpha.1`**（`cd5ef81481`），未修改官方内核源码。

## 阶段记忆

- 投标、实施与投资工作流的每个阶段均有机器可读 `consumes` 声明。
- handoff 按版本追加写入项目自己的 `.agent-pi/business/<module>/<projectId>/orchestration/handoffs/`，包含输入修订、正式成果哈希、能力包状态、人工决策、已接受要求和有限长度状态胶囊。
- 阶段提交先验证必需的前序 handoff；写入失败时不会把阶段误标为完成。
- 旧项目在工作台盘点时按阶段顺序补建可验证的 handoff；无法补建的阶段明确阻塞，不伪造记忆。

## 精准失效与人工保护

- Official Outputs、登记源文件或能力包发生变化时，根据 `consumes` 依赖图只失效源阶段及其传递下游。
- 重置阶段、撤回审批或对已冻结阶段提出新变更要求，也会使原基线失效。
- 预览器保存或删除冻结成果前，显示受影响阶段以及是否需要重新人工确认。
- 工作台逐阶段显示 `基线 vN`、前序基线版本、待生成记忆或失效原因；失效后的人工冻结决策会被清除。

## 上下文与恢复

- 绑定项目的主对话每轮通过动态 `systemPrompt.context` 注入不超过 12,000 字符的项目状态胶囊。
- 胶囊只给出阶段状态、少量摘要、handoff 路径和哈希；精确事实按需回读磁盘成果，不把整套标书反复塞进上下文。
- N3 等量级的约 24 MB / 600 万 token 风格输入已覆盖上下文预算、进程重启、外部改稿检测和压缩后重新组装测试。
- 项目价格、业主条件和项目假设只进入项目 StageMemory；通用规范进入知识库；只有用户明确认可的方法才允许沉淀为 skill 或工作台模块。

## 会话事务监控

- 点「继续推进」后，即使阶段稿已因去重记录标记为派发，也会真正提交并启动当前主会话事务。
- 已提交事务按主会话与专业项目持久化；页面或应用重启后自动恢复，暂停状态也保持不变。
- 主智能体在已授权阶段内因“小批次是否继续”而机械停顿时自动接续；投标/不投标、重大风险、价格基准冻结和最终提交仍必须人工确认。
- 全局自动唤醒、无事务推进和越过人工门禁仍保持关闭。

## 兼容性

- PageIndex、MiniSearch、BOQ 单元格溯源、证据账本、七阶段流程和三个人工冻结门保持原位。
- 3.5.0 不改变 DSH 的模型循环、预设、压缩器或官方源码。
