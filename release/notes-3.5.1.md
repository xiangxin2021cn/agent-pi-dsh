# Agent Pi DSH 3.5.1 — 投标执行止损与交付门禁修复

本次同版本替换修复投标任务反复扫描、重复派活和偏离最终交付目标的问题。DSH 主智能体仍是唯一负责语义判断、任务分解和子智能体派活的“大脑”；专业工作台只负责项目契约、磁盘事实、人工门禁和明确的一轮派发。

DeepSeek Harness 已固定到官方 **`dsh-v0.1.2-alpha.3`**（`dd6322d604`），未修改官方内核源码。产品兼容层适配了 alpha.3 独立 Chat projection，并阻止已移除的 SQLite 会话持久化模块混入发布包。

## 核心改动

- “继续推进”严格变成一次点击、一次派发；监控只观察 DSH，空闲后核对一次盘面，不再自动恢复、自动推进或机械回灌子会话。
- `execution-ledger.json` 只承担可选稀疏遥测，不要求心跳；项目总目标、阶段 handoff 与磁盘成果才是恢复和继续执行的业务基线。
- 项目登记持久化总目标和最终交付物；阶段切换不沿用上一阶段的执行计划和任务。
- 招标分析按整阶段覆盖核验，优先复用既有 Official Outputs，只对缺口和用户新要求定点修订。
- BOQ 核验修复后缀拆分、短描述、仅费率行和 PC/C 项识别，避免把合法清单项误判成缺口或重复计价。
- 最终提交冻结新增正式输出根目录约束，并核验递交清单、审计记录、真实文件和 SHA256 的路径绑定。
- 适配 alpha.3 长会话渲染、断线判定、图片与队列交互改进；Codex 任务结算和用户要求监听改从 Session 与 Chat 双投影合并读取。

## 验证重点

- 投标 Host 227 项、真实 DOM 134 项、业务核心 125 项测试通过；类型检查与 Windows 冷启动烟测通过。
- 一轮任务完成后监控不会再次派发；阶段切换不会继承上一阶段执行态。
- 最终冻结拒绝非正式输出、路径错绑、缺失文件及哈希不一致。
