# Agent Pi DSH 3.8.1

本版完善要求驱动的投标编写：将评分原文、章节计划、企业材料、工程依据与当前成稿关联起来，在主对话、本次任务和专业化工作台展示同源状态。具体用法见 [3.8.1 使用指南](../docs/3.8.1-user-guide.md)。

## 具体改动

- 扩展已有评分与响应模型，登记评分原文、子点和分档条件，保留通过/不通过、门槛及加权评分的不同含义。
- 补齐响应记录的工具写入入口；章节可关联多项要求和评分点，区分原件引用、条件化改写与项目生成。
- 材料复用检查主体、用途、适用条件、有效期、授权与可用性；沿用已有知识版本，不重复建设企业资料库。
- 增加当前成稿的真实文件哈希、文本/Markdown/DOCX 定位和内容审阅记录，检查评分子点的成稿对应。未自动定位的格式保留待复核。
- 来源、要求、材料或成稿变化时，标记关联响应待复核；仅保存复核回执不再让无关旧投标能力包全面过期。
- 本次任务增加“响应对照”，工作台展示同一份详细记录，主对话展示进度与关键缺口。计划、证据、成稿和复核分别表达，未读取资料仍独立保留。
- 工作台浏览其他项目时，不再用当前对话错误恢复该项目的执行监控；监控按真实会话绑定恢复，防止切换时串用状态。
- 中国工作台新增“评分与章节响应策划”“技术标编写与逐项复核”，同一要求编号连接中国资料核对与通用章节记录。共享响应工具不依赖南非投标插件。
- 中国与其他投标模块的同名项目分别保存账本和复核记录；已登记来源被替代或不可读时，相关旧响应不再显示已复核。
- 修正模板优先级：招标人强制格式优先；历史参考样稿可按本项目要求重组，不再强制复制章节数。
- 插件市场升级 1.66.8 → 1.66.9，产品独立 Codex 执行器升级 0.160.0 → 0.160.1。其他核心插件已核查，详细来源与验证见 [插件更新记录](../docs/3.8.1-core-plugin-updates.md)。

## 怎么使用

选择项目资料并绑定适用投标工作台，在主对话输入：

> 请按招标文件和补遗策划本项目技术标，先提取强制要求、评分点和格式，建立章节与材料计划。再使用本项目工程依据编写，逐点检查当前成稿，并在响应对照中保留缺口。

在“本次任务 → 响应对照”或专业化工作台查看原文、章节、材料、成稿及待复核原因；从主对话继续补充材料、调整方向。专业深度用于提高专业论证和审阅要求，关闭后仍保留基本来源和响应检查。

## 升级兼容与边界

- 应用版本为 3.8.1；沿用官方 DSH `0.2.1-alpha.1` / `ec48669f48ac81bac353fc646e7cf9c57241242f`，保留完整 Univer Office 0.3.6。
- 3.8.0 项目和工作流快照保留，新建中国项目使用七阶段。旧项目也可通过对话使用新响应能力，不自动改写历史阶段。
- Windows 继续保留开箱即用 BIM；BIM 与 CAD 原生构建输入未变，复用原已审计运行库及对应源码归档，保留原来源版本。
- 评分条款和材料仍需助手依据实际资料登记；本版不保证 OCR 无遗漏，不提供实际评委得分、中标概率或自动交易提交。
- 文本定位、文件存在和版本检查不代替材料真实性、专业语义、版式、签章或最终人工决定。
- 本文件随本地版本提供；GitHub 发布状态、平台安装包和最终验证范围以实际发布及构建回执为准。
