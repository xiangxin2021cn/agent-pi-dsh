# Agent Pi DSH 3.3.2 — 知识库完善，内核 0.1.1-rc.2

**3.3.2** 的重点是把**本地知识库做成能日常用的工作台**：独立入口、先落盘再解析、对话整理成知识包、用户模板、分类子目录、`.apkb` 传递、MinerU 表格能看。内核钉在 DeepSeek Harness **`dsh-v0.1.1-rc.2`**。没有新的会话库格式断裂。

细项仍见 [notes-3.3.3.md](./notes-3.3.3.md)。

## 这版你先测什么 / What to test first

本包补丁：知识库「新增子目录」和「归入 → 新建子目录」改为页内输入框。旧包在 Electron 里点了没反应（系统 `prompt` 不可用）。删目录 / 删条目同样改为页内确认。

覆盖安装**不改** `%APPDATA%\agent-pi-dsh-desktop\dsh-home` 里已有知识库。请**完全退出**再装（关掉托盘）。若提示 `app.asar` 被占用：退出 Agent Pi DSH，并暂时关掉占用安装目录的编辑器。未签名：SmartScreen 选「仍要运行」。

1. 左侧「专业化工作台」下面点 **知识库**，应直接进同一页。
2. 本页选 PDF / 拖入：只进**原始文档区**，不要自动解析。再点 **解析入库**，看进度和「已入知识库」。
3. 主对话贴上 PDF，发送「把这个 PDF 准确整理完整内容，做成知识包再入库。」只贴文件不说话不应进库。
4. 把一份自己编好的好文档入库为 **用户模板** 并勾选「本次任务选用」，新开一轮看稿面是否复刻格式/大纲，而不是抄模板里的项目事实。
5. 点「新增子目录」应弹出页内输入框（不要没反应）。规范类条目能否归到子目录（如 COTO 2020）；「导出」打出 `.apkb`，再在本页导入应回到原分类/子目录。
6. MinerU 解析稿预览应是 Markdown 表，不应满屏 `<table>`。

Windows 安装包：[`Agent-Pi-DSH-3.3.2-x64.exe`](https://github.com/xiangxin2021cn/agent-pi/releases/download/v3.3.2/Agent-Pi-DSH-3.3.2-x64.exe)。macOS arm64 / Linux x64 由同一 Release 上的 CI 回传。

## 知识库完善 / Knowledge base

索引按**这份文档自己的编排**切条款：章/节/条、`Clause` / `Article` / `Section`、`A1.2.3`。COTO 只是夹具。检索是 MiniSearch BM25，不是向量库。

### 两条入库路，同一套索引

**本页导入。** 左侧栏在「专业化工作台」下面新增 **知识库**；工作台顶栏入口仍在，两边是同一页。选择文件或拖入先落入 `knowledge-base/originals/`，点「解析入库」才抽文本或走 MinerU。也可以贴路径：原文件、知识包文件夹、MinerU 产物文件夹。

**对话导入。** 贴上文件后发送「把这个 PDF 准确整理完整内容，做成知识包再入库。」（也可说知识库、入库、知识包、准确整理、完整内容、全文转录）。对话只生成 `…-知识包/`；写好后，右侧对该文件夹或 `pack.json` 右键 **一键导入知识包**。普通文件仍可右键 **一键导入知识库**。页内第二张卡写着这句提示词。

### 解析过程看得见

选文件不再自动解析。点「解析入库」才开工，MinerU 有进度条和步骤说明；条目带上「已入知识库」时给出成功提示。来源芯片会标「知识包 / MinerU 解析稿 / 本机文本层 / 原文入库」。

### MinerU 表格收成能看的 Markdown

官方 MinerU 把表写成 HTML。入库落稿现在把 `<table>` 收成 GitHub 风格 Markdown 表，并把 `\- Scope` 这类转义列表还原。带 `units` 的知识包不改稿。已入库的旧稿点「全部重建」（或再解析一次）就会转表。预览对还没重建的稿做兜底：完整 `<table>` 仍画成表格。

### 对话里由模型自己出图再建知识包

提到「知识库 / 入库 / 知识包 / 准确整理 / 完整内容 / 全文转录」会加载 `kb-vision-pack`。宿主不先转 PDF。模型必须自己调 **`kb_prepare_document`**，再用官方 **`read_image`** 按印刷页复刻。不要 `vision_*`，不要让用户自己截页。

### 用户模板

新增分类 **用户模板**（也认「用户模版」）。把你编好的较好文档入库并勾选后，本轮业务稿复刻它的格式、大纲、章节顺序、标题语域和内容深度；数字、地名、合同号仍走规范、合同和本项目资料。文件名以「模板」结尾或带 `template` 时，右侧一键入库会自动归入此类。

### 分类子目录

分类下面可以建子目录（例如规范 → COTO 2020）。已入库且文件名能认出的章节会自动挂上，认不出的不乱建。每条可「归入」；删除子目录只拆节点，不删文件。

### 传递包 `.apkb`

已入库文件、有文件的子目录、以及本机技能（不含出厂捆绑技能）都可以导出 `.apkb`。这不是 zip，普通工具打不开。对方在同一页导入，条目回到原来的分类和子目录，技能写入本机技能目录。

### 解析稿要能读

知识库预览打开的是 `manuscript.md`。对话整理规范/合同/用户模板时，模型必须把解析稿改写成可读 Markdown：章/节/条用标题、目录用列表、表格用表，对得上印刷页。

页顶四张卡片写清：本页导入、对话导入、用户模板、传递包。
