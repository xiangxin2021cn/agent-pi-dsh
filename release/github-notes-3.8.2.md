## 具体升级内容

### 1. 官方内核与执行兼容

- 固定官方 [DSH 0.2.1-alpha.2 / d743267](https://github.com/deepseek-ai/deepseek-harness/commit/d743267388641bc76f17c45ce8b4c231aed1d32c)，沿用匹配锁文件重新构建，官方源码保持干净。
- 纳入上游聊天折叠与滚动、切换会话高度、输入焦点、计划确认和模型可用性等改进。
- 适配新版历史查询包位置及插件身份校验；目标驱动和辅助 Codex 通过明确的产品实例接入，定向迁移旧设置，保留启停和参数，避免重复执行或模型选择丢失。
- 两个执行入口加载上游编译后的 JavaScript，修复安装包默认 Node 环境下因 TypeScript const enum、参数属性产生的导入失败；实际包内导入均已验证。

### 2. CAD 读取、预览与算量依据

- **DXF 流式写出**：不再把整个数据库拼接为一个 JavaScript 字符串，解决原项目的 `Invalid string length` 输出失败。
- **磁盘索引和分页**：大型 ASCII DXF 的读取不再受旧 128 MiB 内存入口阻挡；保留原始组码及内嵌二进制，按图层、实体、块、布局、文本等范围查询。
- **DWG 解码游标修复**：修复解压区段较大时的位位置溢出。验证图纸中原有的 **1,111 条块名为 0** 的错误已恢复；8,414 条 INSERT 与独立清点一致。
- **统一修复版解码器**：二维预览采用独立新入口，复用经过核验的 patched host WASM，并隔离旧 worker/WASM 缓存；原 clean viewer 的资产与来源身份继续保留。
- **内嵌对象逐个处理**：可清点、提取和查看 OLE 图像及 PNG，保留完整原始载荷。结构清点、普通查询和各内嵌对象分别记录，分页及后续提取不会覆盖之前观察。
- **缓存与来源核验**：核对原 DWG、完整 DXF、引擎及代码版本；转换中来源变化或旧缓存无法证明来源时重新处理。
- **缺口反馈接入任务**：转换警告、导出差异及未完成展开写入工程问题与任务发现；在工作台查看来源、问题和内嵌图像，在主对话补充材料或调整范围。

## 功能入口：主对话、专业深度与九个工程插件

先打开具有工作目录的主对话，提供本次资料并说明目的。智能体根据目标、可用工具和已有材料选择操作；**说到某个关键词不保证已自动执行对应工具**，应核对实际工具结果、文件和工程记录。

“专业深度”调整证据、方法和审阅要求，**不是 BIM 或 CAD 引擎的启动开关**。关闭它仍保留单位、来源、重复和未知条件等基础检查。普通对话可以按会话建立工程账本；绑定工作台项目后，使用对应项目的共享记录。需要计算时，由助手登记来源、参数、规则和依赖，再运行具体专业工具，用户不需要填写工程 JSON。

| 插件 | 使用入口和作用 | 结果位置 |
| --- | --- | --- |
| 工程宿主 | 主对话中的工程项目工具，保存来源、对象、覆盖、规则、运行和依赖 | “本次任务”和工作台的“工程数据与计算” |
| CAD | 对话读取 DWG/DXF；文件区打开二维预览；逐范围清点、查询及提取内嵌图像 | 文件预览、工程观察及缺口 |

## 可直接复制的使用方法

### A. CAD 图纸：先覆盖，再算量

> 请读取这套道路/市政/结构 DWG。先清点图层、布局、块定义、块引用和全部内嵌对象，登记文件版本与未支持内容。区分料表、构造图和标识，逐一查看内嵌图像。先列独立的图纸与构件覆盖清单，再对已确认尺寸计算工程量；未读取、单位不明、外参缺失或未完整展开的部分单列缺口。

文件区点击 DWG 打开二维预览；存在缺失字体时使用“导入缺失字体”后核对标注。大型 DWG 处理需要时间，验证原图桌面开图约 170 秒，仅是该样本的观测结果。到已绑定工作台项目页中的“工程数据与计算”，或“本次任务 → 任务概览”同名面板查看来源及问题，已有内嵌图像时点击“查看内嵌图像”。

> 先计算已确认的混凝土，逐项给出构件、尺寸、单位、计算式及图纸位置。模板面积如需另外推导，请明确方法、接触面与扣除依据，不把它写成已有专用模板算法。不要把未识别的三维实体、样条或未完成块展开计为零，也不要混入合同计量、加工或采购口径。

若转换缓存来自旧版，让助手重新读取原 DWG 的 inventory，并核对新转换的来源、警告和差异；直接重新打开旧 DXF 不能修复它已经丢失的内容。

### B. PDF CAD 图纸：按页和视口核对

> 请先读取本套 PDF 的全部页目录和带坐标文字。对于扫描页及复杂详图，从原 PDF 按指定 DPI 生成高清局部 ROI 或重叠分块，并逐块记录观察。需要量取时，调用土建市政插件的同页视口标定，使用当前页、当前详图的已知尺寸并保存标注依据；不要直接把像素、DPI 或纸张尺寸当作实际工程尺寸。

渲染图像和生成分块计划不等于已完成识图。比例标定不能跨文件版本、跨详图或非均匀缩放视口复用。

### C. 开箱即用 BIM：检查、生成、回读、预览

Windows x64 的引擎已随安装包分发，默认不需要另装 Python 或 conda。先发送：

> 请实际检查当前 BIM 引擎是否可用，报告正在使用的 Python 路径和 IfcOpenShell 版本；先不创建模型。

正常应调用 `bim_engine_health`，使用安装目录内的引擎。随后可体验一个明确参数的简单模型：

> 请创建演示用 IFC4，只建一根矩形梁 B1。局部 X、Y、Z 尺寸为 6、0.3、0.5 米，最小角点在工程坐标 (0,0,0)，绕 Z 轴 0 度。保存为工作目录的新文件 bim-demo-01.ifc；已有文件请另取编号。生成后登记文件来源，回读核对尺寸和位置，计算几何体积并生成三维预览，给出实际文件路径与待复核项。

该演示矩形体体积应为 **0.9 m³**。生成文件、登记来源、回读和请求预览是不同操作，需由助手实际完成。“本次任务 → 任务概览”或已绑定工作台的“工程数据与计算”中可查看实际网格，旋转、缩放和选择构件；“查看 IFC 文件”本身不会自动运行网格预览。

已有 IFC 可要求分批清点单位、构件类型、GlobalId、属性及原生数量，再计算指定对象的几何净量、毛量和开口扣除，逐批报告剩余覆盖。macOS/Linux 需要配置兼容的外部 IFC 引擎，未内置 Windows 运行库。

### D. 钢筋 BBS 与中国平法

> 先区分图中是否已有完整钢筋料表。对真实料表核对规格、形状、长度、数量、单位和重复，再计算。若是中国平法图，请先确认适用规则版本、已授权规则材料、集中与原位标注作用范围、保护层、锚固、搭接、弯折、抗震等级及节点条件；缺少条件时列出问题，不自行补值。分别保存几何、计量和加工口径；采购量另外根据真实损耗及采购规则登记。

本版提供结构化标注/料表、规则采用和逐组计算链，**不是完整 G101 自动识图或全图自动下料系统**。需要项目适用、来源明确且已复核的规则包；不内置未经授权的图集全文。加工结果仍需专业审校及实际加工约定。

### E. 技术标：要求和评分驱动

在工作台选择适用投标流程，并绑定当前对话，再发送：

> 请根据当前招标文件、最新补遗和企业资料策划技术标。区分资格与实质性要求、评分原文及子点、提交格式和材料缺口，按招标人强制目录建立章节计划。企业证书和业绩引用真实原件，施工部署、进度和资源使用本项目图纸及已复核工程依据。明确的先做，涉及承诺或方案取舍再问我。

在“本次任务 → 响应对照”查看来源、章节、材料、实际成稿和待复核项；工作台及主对话显示同源记录。仅上传招标文件不代表评分矩阵已建立。“已规划”“当前稿已记录复核”分别是登记与检查状态，不表示官方评分、资格验真或保证中标。普通聊天不会自动变成投标项目；已有工作流快照不强制重写。

### F. 纠正方向和导出成果

> 这份补遗替代旧版工期条件，请列出受影响的计算、章节和成果，复核关联部分；其他已确认资料继续使用。

> 请从当前工程账本导出 XLSX 工程量表、HTML 计算书和完整 JSON。逐项保留来源、单位、公式、覆盖与未知条件；把缺口和依赖变化同步到本次任务，不自动授予验收或加工批准。

Office 使用原有文件预览/编辑入口；AnySearch 使用原有设置中的凭据和主对话检索工具。插件被禁用或卸载时，历史记录保留，但缺失 provider 不能作为当前计算已通过的依据。
