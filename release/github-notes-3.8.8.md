# Agent Pi DSH 3.8.8 主线版

本版将 3.8.7 的主线维护工作正式归入 3.8.8。本次公开发行仅包含主线版；投标专版的分支、安装标识、用户数据及升级通道保持独立。

## 界面与插件维护

- 左侧折叠后常驻展开图标，右侧资源栏展开键位于窄栏顶部；窄屏专业工作台保留恢复入口及键盘焦点提示。
- 插件市场升级官方 1.73.9，主页面增加“检查市场更新”，发现新版本后复用既有更新和来源替换确认。只有明确的随包源可走在线更新，用户私有同名链接仍受保护。用户独立切换到社区原版时会明确提示本应用的市场界面适配不随之保留，并保留可验证的来源回退。网络失败不显示为“已是最新”。
- 市场自检只查询市场自身的更新来源，不再等待精选目录或其他插件的请求；全量检查复用一次目录读取。未取得版本的结果明确显示“未确认”，保留其他插件及已成功自检的更新状态。
- 重载后的旧失败行明确标注“历史操作结果”，保留原失败原因与日志。本次成功读取且确认存在的安装清单可另行显示“当前已安装；清单声明”，不会把历史错误当作当前故障，也不据此宣称插件健康或实体版本已经核验。
- 恢复排队的更新和卸载前，必须取得本次页面新鲜、有效的安装与更新快照；读取失败或返回畸形数据时保留队列，不用上次页面缓存自动放行执行。
- 针对 pnpm 10 与当前官方 pnpm 11 的依赖布局冲突，在 DSH 加载插件之前进行受控迁移：保留原依赖树和清单，只补齐已声明而锁文件缺失的本地链接，保持注册表解析冻结，禁止生命周期及 pnpm hooks，核验依赖入口；失败恢复原树并验证。中断或无法确认恢复时停止启动并保留备份，不能误建空 profile。
- 打包只排除仓库根开发文档，保留插件声明的介绍与预览图。新的 DSH receipt 对声明路径、文档存在和实际库存做检查；非法路径及链接逃逸仍拒绝。
- 本次维护文案覆盖语言选择器的十种语言，并修复切换语言后市场检查结果保留旧译文、阿语窄屏恢复键重叠及 Agent Teams 入口说明。侧栏十语四十态已验证；官方原生韩语/阿语及部分专业长文继续按原有规则回退英文，不宣称全应用或社区市场已全文翻译。

## 插件与 Office

完整 Univer Office 升级 0.4.0：保留官方 Host、Gateway、Worker、Viewer、技能和许可证，按上游改用 Node SQLite，移除废弃的 libsql 依赖。已验证旧 v0/v1/v2、当前 v3 文件与重开，以及真实 Word 页边距/横向和表格导入导出。上游仍有 CSV 导出、PPTX 图像等预期失败用例，本次不宣称修复这些既有限制，也不将测试夹具等同客户文档精度验收。

AnySearch 0.1.8、Injector 0.3.5 与 Router 的固定源已核对，未发现更高稳定发布。用户插件 IM 5.9.1 与邮件 0.21.2 经当前内核的隔离 API、V4 会话接续及无账号注册验证；兼容许可仅覆盖已审核版本、入口和内核源，不放开未知版本或被修改的入口。真实账号登录、收发及可选图像运行库不属于该证明。本机更新和备份结果以交付记录为准；通用安装包不包含用户账号或私有插件。

市场维护相关回归 25 项、补丁写入、回退与路径防护场景 8 项通过，覆盖纯逻辑、loopback 服务及隔离 DOM；这些结果不等同于全平台验收。本机 11 文件市场修复已应用，保留备份和原失败记录。

Windows 已安装应用在正常重启并完成 profile 加载后，原工作区、旧对话和资源树恢复；市场显示 1.73.9 和 36 个已安装项。目录仍在加载时执行市场自检，9.25 秒内已观察到“当前 1.73.9，没有确认更高版本”，目录同时仍在加载；该数值是观察上限，不是精确请求耗时。任务面板的两条旧 store 错误明确标注“历史操作结果”，各附“当前已安装；清单声明：5.9.1”，原红色失败内容完整保留。此轮未发送模型请求、重试、清空历史或执行插件安装。

上述实机结果针对本机已安装应用及同一市场补丁。最终 Windows 安装包已从冻结提交 `28888149e1249661945e17c29d9baf8a725712e1` 全量重建并独立验包：688,208,876 字节，SHA256 `b661d52ac275db598c68f7ac291f47d80c440e498a0d9c40dfdb1898c485e8af`；比原公开 3.8.7 Windows 包减少约 44%。安装器内嵌载荷、559 项依赖、完整 Office、知识库、技能、模板及工程组件核验通过；本轮未执行新安装器或访问原项目。macOS/Linux 通过各自 CI 的原生模块、终端、运行时封装及资产校验；两种 Mac 架构另通过最低系统版本扫描。这些 CI 结果不等同于 GUI 实机安装验收。

## 如何外派本地 Codex

主执行者仍是 DSH。移除的是产品自定义的 Codex 主执行器、设置入口和冗余 SDK，并未取消官方 `subagent_oar` 外派能力。DSH 可根据独立任务需要选择可用的 Codex 或 Claude；用户无需输入固定口令，也可以明确说：

> 把这个独立代码修复任务交给本地 Codex 执行；由 DSH 整理任务约束、检查实际修改并汇总结果。

本地 CLI 需已经安装并完成其原生登录。外派仅在实际插件、运行时和当前权限允许时执行；请求不会自动扩大权限。工作者不会自动继承主会话、知识库、范本和专业工具，DSH 需明确传递相关范围和约束，并根据真实返回和实际文件验收。无法调用或结果未知时应报告具体缺口，不能以普通文字声称已经外派。旧产品 Codex 历史保留只读。

## 长程任务与组件

“本次任务”默认折叠，保留原会话、项目、约束和人工决策。宿主跟踪持久派发意图、原生收据、来源版本及外派生命周期；不对未知副作用盲目重派。取消 API 金额上限，继续保留回合、已知 token、时间、无进展及权限边界；外部 CLI 未报告的 token 不记为零。

借鉴 Superagent 的恢复、授权及外循环思路，并非整体加载其研究原型；尚未实现通用 Source/Thread/SQLite Engine、跨进程租约或统一保存导出 Outbox。官方 OAR 是执行适配器，不是另一套主任务账本。沿用已审核的 DSH `ce7073d51254c26cd63b22a60835b8f948deb447`，保留完整 Univer、知识库、技能、模板 DNA、CAD/PDF、BIM 和项目计划运行时。

DWG 预览直接使用 DWG 解码；当前工程 `cad_read` 算量链仍包含 DWG 转 DXF，不能将预览成功等同于直接 DWG 算量或原客户图纸的精度验收。实际发布构件的验证范围与安装包 SHA256 以本次交付记录为准。

## 主线公开发行

Windows 安装包、macOS Apple Silicon / Intel 的 DMG 与 ZIP、Linux x64 AppImage 与 DEB，均使用最终验收的 `v3.8.8` 主线应用源码及本版新生成的运行时载荷。Node.js 统一为 24.22.2，Electron 为 45.2.0；两种 macOS 架构要求 macOS 15 及以上。macOS/Linux 不内置 Windows 专用 IFC 运行库，仍需配置兼容的外部引擎。

发行资源共 23 项，包含各平台安装包与校验文件、Windows 构建回执、新运行时载荷及三对 CAD/BIM 对应源码。对应源码保留原审核版本、原名与 SHA256；平台包全部重新构建。投标专版、原用户项目和已有公开版本的标签及资产均不在此次发布变更范围。
