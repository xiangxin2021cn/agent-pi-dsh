# 招标文件解析深度标准（结构门槛，不含项目事实）

本文件约束 **结构、章节和深度**，不提供任何具体标的数字、地名或合同号。项目事实只能来自本项目已登记资料；缺原文就标缺口。禁止把上一单（含任何 N2 / SANRAL 示例）的金额、里程、罚款抄进本项目。

用户若在知识库勾选了「用户模板」，只许复刻版式与目录，不许复刻事实。

## 硬性落地的五份客户稿

写在 `Agent Pi Outputs/<projectId>/document-analysis/`。文件名必须如下（不要带合同号后缀）：

| 文件 | 必须覆盖 |
| --- | --- |
| `招标文件总结.md` | 基本信息表；卷册体系；资格门槛；评标各 Stage / 分数线；合同与商业条件；A/B 返标清单；时间节点；风险 |
| `工程量清单分析.md` | 总价构成；各 Schedule / 分册金额与占比；PC Sum / Provisional / 待报价分层；结构物暂定 vs 须自算；报价策略与风险 |
| `工程范围与技术规范总结.md` | 合同数据（工期 / 保函 / 预付款 / 保留金 / CPA / 罚则 / 分包上限 / 工时）；定价结构与结构物清单；范围与规范体系；HSE / 环境 / 目标企业 |
| `合同特殊条款与规范修订总结.md` | 通用条件对照（定义 / 优先级 / 支付 / 分包 / EOT / 罚则 / CPA / 索赔）；规范逐章修订；风险条款清单 |
| `技术标文件要求汇总.md` | 返标总表；A 系列逐项；B 系列字段与评分；功能性评分表；方法说明书（B8 或本标等价）深度与联动 |

另外仍须：逐份源文件解析稿、`项目特征.md`、`招标文件解析总报告.md`。总报告是综合指针，**不能单独代替**上面五份。

## 深度门槛（机械验收）

每份至少约 3500 字，并且正文出现对应章节词（资格 / 评标 / PC Sum 或暂定 / 特殊条款 / 返标 Form 等）。过短、缺文件、缺章节时 `complete_stage` 会被拒绝，工作台「检查」和监控会列出具体缺口。

补齐时只写列出的文件。不要重解析已经 done 的源文件，不要另起一套文件名。

## 写法

- 关键数字、日期、罚则、人员资质必须带来源令牌 `[src:…]` 或 `[kb:…]`
- 表格优先于散文；对照表写「通用条件原文要点 / 本标修订」
- 本标没有的制度（例如某国注册等级）标缺口，不要用记忆补
