# Professional task execution

Read `professional_task status`, including a parent task in an assigned native child session. Understand the actual objective, audience, selected sources and required output before executing. Inspect provided materials first. Ask only questions whose answers change scope, methods, material assumptions or delivery through the native question mechanism. Ordinary documents, tables, research and reporting do not require creating a workbench project.

Maintain a brief and ordered plan with actual capability IDs, dependencies, evidence gaps and supplements. Assess actual tools/skills/plugins against input formats, project jurisdiction, standard version and output needs. Availability alone does not prove suitability. Use native alternatives where suitable, otherwise describe concrete limitations. DSH owns execution, permissions, continuations and stopping.

Use `parse_source` to record selected source versions and every PDF page. Complete each batch and review printed tables, drawings, attachments and addenda with suitable native tools. Text extraction is not visual or professional review. Register missing referenced sources. Link requirement/scoring locations, calculation inputs and files by stable IDs. Never scan an unselected folder as the task corpus.

Public task-related read-only diligence is permitted unless restricted. Record actual URLs, access/effective dates, locality and applicability. Verify current primary sources for laws, standards, wages and taxes. Public data cannot establish private project geology, bidder capacity or a supplier's formal quotation. Conflicts and assumptions remain distinct. Respect no-web restrictions. Contacting suppliers, uploading confidential data and committing bids require actual authorization.

BOQ work derives every selected item's scope, measurement, method, productivity, unit resource consumption and sourced rate; retain deterministic calculations and formula workbooks. Distinguish resource totals, scheduled peaks, direct cost, commercial transfers and tender quotation. Reconcile actual rows and evaluate material assumption sensitivities. Implementation plans inherit that basis. Returnables follow actual tender templates, conditions and scoring points, including forms, declarations and signature/authorization state.

Apply the task-specific writing preset automatically. Follow customer terminology, template and language. Each section delivers evidence, reasoning, a calculation or executable steps. Remove promotion, repeated conclusions and generic commitments; never fabricate specificity. Review actual contents, arithmetic, requirement coverage and cross-file consistency. Record technical review separately from structure/writing checks. Run `professional_task check` and native `present`; only the customer can accept or confirm signatures.

After changed inputs, read the latest revision, review affected derivations/plans/files and preserve unaffected work. Children report assigned results through native mechanisms instead of replacing the parent's entire task.
