# Tender Writing Contract

Operational skill: `tender-formal-writing`. This file remains the full writing-contract reference.

Applies to **every** tender-workbench stage: document-parse memos, BOQ workpapers, project-characteristics notes, methodology, programme/resource narratives, cash-flow notes, formal returnables (Work Plan DOCX and the like), and any chat summary a bid team will read.

This is a writing contract, not a completeness waiver. Source locators, validation, and readiness gates still apply.

## What the artifact is

A bid-team paper for **this** tender, written as an estimator / QS / construction planner would write it for overnight internal use or for the employer's returnable:

1. Uses the **employer's** terms, clause numbers, item codes, units, and measurement/payment language from registered sources.
2. States **bid consequences** (price, method, programme, compliance) with useful locators.
3. Matches the required **language and template heading tree** when a returnable or bound template exists.
4. Leaves gaps as gaps. Does not paper over missing evidence with fluent prose.

Working memos are decision notes. Formal deliverables are the employer's document, not an AI report about the tender.

## Ground in the tender

- Prefer the source's own wording over generic construction-textbook synonyms.
- Keep employer-defined names unchanged (COTO, COLTO, FIDIC, chainage, P&G, returnable form IDs, BOQ codes).
- Formal chapters follow the employer's TOC / bound template, not a blog or “key takeaways” outline.
- Depth matches **this** specification, BOQ, and confirmed boundary. Do not import method theatre from unrelated sample projects.
- Write in the language the tender or user required. Do not mix unexplained bilingual filler.

## Strip AI flavour

Do not use chatbot scaffolding or marketing diction. If a sentence could appear in any other job, delete it and write the clause, quantity, or open question instead.

Typical rejects (not exhaustive):

| Flavour | Examples |
|---|---|
| English filler | Furthermore; Moreover; It is important to note; In conclusion; In today's rapidly evolving; leverage; robust; seamless; cutting-edge; delve; landscape; key takeaways; comprehensive solution |
| Chinese filler | 综上所述；值得注意的是；在当今；赋能；全方位；一站式；不仅…而且…；首先/其次/最后（空骨架）；确保万无一失；全面覆盖；助力；赋能投标；深度剖析 |
| Meta dump | documentId / batchId / reportPath catalogues; Working Folder tours; knowledge-pack tutorials |
| Fake completeness | “全面覆盖评标要点”; “确保方案科学合理”; generic HSE/method essays the tender did not ask for |

## Stage recipe

| Stage | Customer-facing artifact |
|---|---|
| Document parse | Per-file tender reading note: hard constraints → pricing/method/programme implications → risks/gaps. One filename header at most. |
| Project boundary | Confirmed fence for this tender: registered KB/spec/bidder files, extracted plant/labour, measurement, currency, organisation. Not a jurisdiction essay. |
| BOQ pricing | Item workpaper in this BOQ's codes and the governing spec/measurement clauses. No textbook method paragraphs that do not price the row. |
| Bidder commitments | Decision record in the user's terms, reconciled to calculated demand. Not a motivational summary. |
| Execution / programme / cost | This job's method, logic, and numbers from ready packs. Sequence and resources must be constructible from the BOQ and commitments. |
| Formal submission | Employer's returnable: template headings, evaluation language, no internal audit matrices unless requested. |

## Red flags — rewrite before handing to the user

- File-catalog or path dump instead of bid consequences
- Generic method theatre or a sample-project TOC
- Synonym-swapping the employer's terms
- Bold-everywhere markdown-blog tone, emoji, or “Key Takeaways”
- Fluent prose that cites no clause, item, or pack
- Claiming completeness where the workspace still has gaps
