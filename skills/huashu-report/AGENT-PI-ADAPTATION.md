# Agent Pi 报告编制适配

上游：alchaincyf/huashu-report，提交 bdc08bee5077462e1300431408c5237438a22d00，MIT（见 LICENSE）。保留原参考资料、图表库和排版基座；render.py 适配跨平台路径、UTF-8 与命令失败提示，chart.py 修正成对柱全部为零或负数时的坐标范围。

- 此技能只在用户确实要求撰写或实质修订专业报告时使用。提及报告、阅读/总结已有报告、报错诊断、普通聊天，不启动报告创作流程。无需开启“专业深度”，也不自动创建专业项目或开启投标流程。
- 先从真实输入推断读者、用途、交付格式；已明确的直接执行。仅缺少会改变成果的关键条件时集中询问，不强制三轮问答或视觉方案确认。用户已有模板和格式要求优先。
- 编制投标报告时，招标文件、补遗、评分办法和用户指定模板拥有格式优先权。先遵循 tender-formal-writing；本技能补充证据、结构、图表与自检方法。不得套用通用“附录不超过 10%”或咨询 deck 样式来删减必交内容。
- 知识库仅使用用户在当前对话选择的资料。示例报告里的数字、年份、机构和结论不能作为本项目事实；需要使用时重新核查一手来源。百分比须给口径、分母/样本量；合同金额、工程量、工期等应给单位、依据和适用条件，不硬套调查样本 N。
- 数据表中的 verified 只能表示已经实际核对来源；缺证据时明确说明，不为通过机械检查而改成 true。机械渲染成功不代表专业结论通过验收。
- 按需读取 references，禁止每次加载全部参考文档或 corpus。四种角色是工作阶段，不意味着必须创建四个子智能体。是否协作由用户的 Team 开关与当前任务需求决定。
- 报告和过程说明使用用户输入语言，除非用户指定其他语言。最终报告保留方法、来源和局限性，去掉安装、工具调用、重试等工程日志。

## 来源与实际交付

创作或实质修订文件时读取 `file-delivery`。重要金额、工程量、工期和技术参数应区分原始事实、用户决定、推算、建议和待证假设，给出来源定位、单位及适用范围；计算保留输入与方法。不能把模型上一轮建议、已选模板或旧项目数字当作本次事实。来源冲突应说明，不能自行混合成一个确定结论。

交付分为创建、实际检查、提供文件入口三步：核对最终保存的真实格式和要求内容；按需要打开、渲染检查版式及可编辑性；文件修改后重查，使用 DSH `present` 交付最终文件。格式检查通过不等于专业内容、版式或编辑保存均已验证，未做的检查须如实说明。

## 本地工具

内容与 SVG 图表可离线编制，联网仅用于用户任务所需的资料核验。需要 PDF 时先检查实际可用工具：Python 3、Python playwright、Chromium，以及 Poppler 的 pdfinfo/pdftotext/pdftoppm。它们是渲染工具依赖，不是云服务；本技能不会在应用启动时安装或运行它们。

先运行 `python assets/check_runtime.py`。缺失时按其结果使用应用已有 Office/PDF 工具完成相同检查，或明确补齐本地依赖后再运行 render.py。不得把 HTML 改扩展名当 PDF，不得声称未执行的渲染或逐页检查已经完成。用户要求可编辑 Word 时交付 DOCX，并使用现有 Univer Office 预览；HTML/PDF 不是 DOCX 的替代品。

脚本和数据表复制到当前工作目录后再修改；不要修改安装目录中的技能原件。长期复用模板只能由用户主动保存、主动选用。
