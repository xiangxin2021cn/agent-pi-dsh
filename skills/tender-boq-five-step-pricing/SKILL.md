# Tender BOQ Five-Step Pricing

Use `tender_capability` as the BOQ five-step pricing system of record. This skill produces the structured pricing basis that later methodology, programme, resource, cost, and cash-flow planning depend on.

**Read [references/schema.md](references/schema.md) before any `replace`.** Call `tender_capability` with `action: schema` and `capability: boq_five_step_pricing` first. The pack is `.strict()`. Top-level keys are only `currency`, `pricingStatus`, `itemBuildUps`, `assumptions`, plus optional `pricingStandard`, `vatTreatment`, `indirectCostPolicy`, `resourceSummary`. Do not put `rateBasis`, `planningBasis`, or `sources` on the pack root.

The required quality profile is `c51_pure_direct_cost_v1`. The C5.1 reference standard is an item-by-item workpaper: each BOQ row preserves its original identity, interprets exact specification and measurement clauses, derives a constructible method and bottleneck productivity, calculates per-unit resource consumption, applies traceable VAT-exclusive rates, and reconciles the pure direct unit rate and item total. A labour/material/equipment database is only a Step 3 rate source. It is never the stage deliverable.

When the child brief includes `methodStandard.path`, open that file and match its derivation depth and workpaper shape. The path is resolved from project `bindings.json` (default: bundled SANRAL C5.1 路床单价推导). Copy structure and craft only. Re-bind every rate and daily output to **this** tender’s site — see [references/local-site-intel.md](references/local-site-intel.md). Do not invent a shallower substitute.

## Guardrails

- Stay in this conversation for the whole tender project; BOQ pricing is a stage change on the same chat, not a new main conversation.
- BOQ chapter batches may be split with **dsh native** `subagent` / `workflow`. Do not call `spawn_session`, `tender_stage` `dispatch`, or invent a concurrency cap.
- Nested children must not spawn further children. If the parent advances while a child is still running, that child may keep the prior stage until finish.
- Use only user-selected sources, registered Tender Workspace records, and explicitly loaded knowledge-base entries.
- Do not scan the working directory as a source corpus.
- Read Official Outputs `项目特征.md` (compiled after document analysis) and any `upstreamDeliverables` on the child brief. Honour contract form, particular conditions, governing specs and amendments, duration, site/geology/climate, working hours/holidays, subcontracting/localisation, and employer-imposed sequence. Do not invent plant, labour, materials, camp, or methods that contradict those characteristics or registered tender sources.
- Honour `brief.evidencePolicy`. Project-characteristic gaps (missing spec PDFs, geology, calendar, subcontract limits) must **not** be filled from model memory. If `webDiligenceAuthorized` is false, do not use the web to invent those facts — keep them unverified and tell the parent session to ask the user to upload sources or force-pass. If true, diligence **only** the listed gaps and record `url` + `accessedAt`. Market-rate `web_search` / `web_fetch` is a **separate, always-on** rule: never skip rate search because the characteristic gate is closed.
- Require ready, non-stale `document_analysis` and `boq_reconciliation` packs. A `project_boundary` pack is optional leftover data — never block pricing on it.
- Price every selected BOQ item individually; never replace item analysis with a summary-only estimate.
- Do not substitute a generic resource database, market-price report, chapter summary, unpriced scope register, or narrative methodology for item workpapers.
- Each BOQ item must cover five steps: scope and quantity, method and productivity, resource consumption, sourced rates and direct cost, reconciliation and risk.
- Keep item direct cost pure: exclude overhead, P&G, profit, general contingency, and escalation. Handle those in downstream commercial planning. All rates are VAT exclusive.
- Keep sourced facts, engineering assumptions, commercial assumptions, and unresolved gaps separate.
- Unverified assumptions may not enter the core conclusion as facts.
- Child agents write **both** the structured JSON handoff (`reportPath`) and the customer-facing chapter Markdown (`markdownPath`). Markdown belongs in Official Outputs (`Agent Pi Outputs/<projectId>/boq-pricing/`). JSON stays in orchestration/reports. Once reports exist, the parent `tender_capability replace`s the pack — do not wait for an Electron runtime merge, and never hand-assemble compressed pricing into the tool call.
- A child retains exclusive ownership of its assigned BOQ range until its terminal structured handoff is ready. The main session must wait, retry, or request user review; it must never derive substitute rows or write the child report after a timeout.
- Key resource rates (fuel, wages, plant hire, cement, aggregates, asphalt, subcontract) **must** be verified with `web_search` / `web_fetch` in this stage; record each hit in `itemBuildUps[].costComponents[].rateBasis.webEvidence` (`url` + `accessedAt`). This is independent of `webDiligenceAuthorized`. Rates that cannot be verified online stay `assumptionStatus: unverified` — never invent a rate.
- **South African highway labour** (ZAR / SANRAL / COTO): read [references/sa-labour-wages.md](references/sa-labour-wages.md). Do not copy the bundled C5.1 路床 wage table (`R250` / `R550` / `R650` / `R850`) and do not use Chinese construction day-rates. Prefer `anysearch_batch_search` with `zone: "intl"` and `language: "en"` (never `zone: "cn"`) for the current BCCEI civil wage determination **and** the gazetted National Minimum Wage, then `web_fetch` the official page. NMW is a floor for general / community labour, not the operator or artisan rate. Contract local-labour / EPWP rates override for the people they cover. Write hits on the labour component `rateBasis.webEvidence`.
- **Site-bound rates and productivity:** read [references/local-site-intel.md](references/local-site-intel.md) and [references/local-productivity.md](references/local-productivity.md). Priority is **enterprise file > human-reviewed project ledger > local web page > international handbook × site**. If setup registered a 工效 / productivity file, copy those numbers and do not overwrite them. If the user later confirms a Markdown edit of daily output or a key rate, treat that as this tender’s reviewed fact and rescale related resource quantities. Otherwise start with `anysearch_capabilities`, then `anysearch_search` / `anysearch_batch_search` (`zone: "intl"`) for this province / metro / corridor. Effective factors, haul, diesel, water, plant hire, and **daily output** come from the site in `项目特征.md`, not from the C5.1 illustration (`2,500 m³/天`, KZN rain factor) and not from Chinese highway norms. Write `当地工效尽调.md`.
- **Supplier diligence and bilingual RFQs:** read [references/supplier-rfq.md](references/supplier-rfq.md). Before `complete_stage`, write `当地供应商尽调.md` (phone, email, URL, `accessedAt`) plus `询价单总表.md` and one Chinese+English RFQ per inquired resource under `询价单/`. Do not invent contacts. If the pack cannot be completed, `tender_evidence waive_pricing` (or `tender_stage force_pass` on this stage) plus `组价依据说明.md` lets planning proceed on web quotes and derived outputs — that basis must stay labelled.
- Numeric fields are plain decimals without thousands separators; allocation weights and effective factors are 0–1 fractions (`0.85`, not `85`). Completeness and BOQ identity are the hard gates.
- **Writing:** Follow tender-intelligence-core `references/writing-contract.md`. Chapter Markdown must be this BOQ's workpaper in spec/measurement language, with AI filler stripped.

## Workflow

1. Call `tender_workspace` with `status`, then call `tender_capability` with `status` for `document_analysis` and `boq_reconciliation`. Call `tender_capability` `action: schema` for `boq_five_step_pricing` and keep that field map; do not guess top-level keys.
2. Confirm selected BOQ item scope, source priority, currency, pricing location/date, and rate basis against `项目特征.md` and the child brief. Pause for user confirmation when those are ambiguous. Do not invent facts the tender files and project characteristics do not support. If evidencePolicy lists a gap, stop and ask the user to upload the source or force-pass for web diligence — do not guess.
3. Use the stage briefs from `tender_stage` (`brief.reportPath` / `brief.markdownPath`) and dsh native subagent/workflow if you split by BOQ chapter. Do not wait for an Electron batch board or `tender_stage` dispatch. Do not enlarge, regroup, or bypass an assigned chapter unless the user asks.
4. Complete all five steps for every assigned item:
   - **Step 1 - scope and quantity:** copy code, description, unit, quantity, and row source exactly; cite specification plus measurement/payment clauses; list inclusions, exclusions, materials, acceptance tests, and method constraints. Use an explicit reasoned `not applicable` entry instead of silence.
   - **Step 2 - method and productivity:** state construction sequence, labour crew, plant fleet, working hours, controlling resource or cycle, theoretical output, effective factor, and the formula. Search this site before assuming a rate (see local-productivity.md). Record optimistic, base, and pessimistic productivity in the same quantity/time unit. Base productivity must equal `planningBasis.productionRate`; duration must cover the BOQ quantity.
   - **Step 3 - resource consumption:** address labour, plant, material, subcontract, transport, and waste explicitly. For every included category calculate consumption per BOQ unit, show the calculation basis, cite sources, and link it to one cost component.
   - **Step 4 - sourced rates and pure direct cost:** for every component record per-unit quantity, unit, rate, amount, source locator, source type, acquisition mode, location, effective date, VAT-exclusive basis, and verification state. Verify key market rates online and attach `webEvidence` (`url`, `accessedAt`, optional `note`); unverifiable rates stay `unverified`. Reconcile category subtotals, unit direct cost, and `itemDirectCost = unitDirectCost x BOQ quantity`.
   - **Step 5 - reconciliation and item risk:** reconcile scope, unit, quantity, production, duration, and amount; record item-specific optimistic/base/pessimistic sensitivity, trigger, treatment, conditions, and unresolved evidence. Do not insert macro political or FX commentary unless it changes this item calculation.
5. The **pack top level** (not each item) must declare `pricingStandard: c51_pure_direct_cost_v1`, `vatTreatment: exclusive`, and `indirectCostPolicy: excluded_from_item_direct_cost`. Missing structured fields, unsupported numbers, unlinked resources, and unverified core rates prevent readiness.
6. When every child JSON report is on disk, the parent reads those reports and `tender_capability replace`s `boq_five_step_pricing` with the merged structured data. Empty replace payloads are not merged by a runtime — you must pass the pack. Do not compress or rewrite chapter Markdown into the tool call; Markdown already lives at `markdownPath`.
7. After pricing is packed, write `施工资源消耗总表.md` to `Agent Pi Outputs/<projectId>/boq-pricing/` from `resourceConsumptions × BOQ quantities`, and `tender_capability replace` `construction_resource_schedule`. Do not wait for a runtime aggregator.
8. Review unverified rates, draft items, and the resource schedule with the user. Confirm bidder commitments (`bidder_commitments`) before planning.
9. After chapter Markdown, write the local-intel pack in the same Official Outputs folder: `当地供应商尽调.md`, `当地工效尽调.md`, `询价单总表.md`, and bilingual files under `询价单/`. If that pack cannot be completed, waive it and write `组价依据说明.md`. Then write `BOQ 组价总报告.md` and call `tender_pricing_workbook` with `action: generate`. This writes `Agent Pi Outputs/<projectId>/boq-pricing/BOQ 组价测算.xlsx` from the packed JSON: Summary + Rates + one sheet per BOQ item. Block titles follow the factory unit-cost analysis layout (`Cost of materials` / `fuel` / `machinery` / `labor` / `Management fees…`). `F=D*E`, block `SUM`, header `RATE` (`E3`) and `PRICE` stay formulas. Daily output sits in yellow `H2`. Do not type over formula cells. Do not rebuild this workbook with openpyxl or a blank Univer sheet.
10. If `univer_*` tools are loaded, `univer_new` → draft worktree → `univer_import` the generated xlsx so the user can edit quantities and rates in chat. Call `univer_execute` with `executeCalculation` before any re-export. Merge or discard the worktree only when the user explicitly asks.
11. Call `validate` on pricing (and review the resource schedule pack). Resolve every error before downstream planning. Initial item cash-flow allocations are optional here; schedule-based cash flow belongs to the later planning stage.

## Completion

Report the pricing pack revision, readiness, BOQ item coverage, C5.1-complete item count, pure direct item-total cost, unverified assumptions, rate gaps, batch status, resource-schedule row count / markdown path, the formula workbook path (`BOQ 组价测算.xlsx`), and audit path. The human-readable workpaper must contain a summary table followed by a full five-step section for every BOQ item. The xlsx is the editable calculation book; Markdown remains the narrative control artifact. Keep both unless the user explicitly requests a formal submission document.
